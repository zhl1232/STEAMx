# Local Vosk course controls experiment

Run `pnpm test:e2e:building-vosk:engineering` for the required CI regression suite. Run `pnpm test:e2e:building-vosk:acoustic` manually for the real speech benchmark; `pnpm test:e2e:building-vosk` runs both. A local Vite fixture on 127.0.0.1:4185 uses the real course controls, capture, model and 3D workspace. Only authentication/course data and microphone input are replaced. No hardware microphone or production database is used. `PLAYWRIGHT_CHROMIUM_EXECUTABLE=/path/to/chromium` selects a local Chromium executable; software 3D does not represent phone GPUs.

`cases.json` retains all expected actions and rejections. Original normal/clear recordings derive from `e2e/building-kws/audio` (MeloTTS, one synthetic female voice, normal and 0.8 speed); this corpus uses fixed 16 kHz resampling. Extra, holdout, independent, unseen and heldout-final recordings use the same offline MeloTTS model at speed 1.0. Overlap is a deterministic mixture; silence/white noise are synthetic signals. The recorded-command case intentionally reuses an exact command waveform to expose speaker/origin ambiguity. There are no human or household recordings.

The test retains strict rejection assertions for known short-negation, overlap, similar-wake and replay failures. A failing acoustic test is not a failed download and must not be hidden by discarding unknown words or relaxing expected results. Repeated start/stop, media coordination, actual track interruption, navigation invalidation and capability/load errors have separate tests.

The application only caches the pinned model archive; test observations contain synthetic transcripts for diagnosis and are cleared between clips. Product code does not retain transcripts or PCM. Prior KWS files and raw cloud experiment reports remain preserved separately; this suite does not claim those old results as Vosk validation.

The fixture now mounts controls through the real 3D workspace toolbar. Cold resources wait for the course, cached bytes are distinct from actual engine readiness, and no microphone is requested during preparation. The normal/slow/negative acoustic expectations are unchanged. Closing capture releases its track, context and recognizer; one standby model remains owned by the mounted course. Leaving the course or pagehide releases both worker levels. Separate tests cover cold/hot cache, conservative network policy, failure/retry, cancelled preparation and engine initialization failure. The original KWS browser suite belongs to the historical KWS head; CI runs the engineering selection. The two `@acoustic` tests keep all recordings and strict assertions in the manual command; they are not skipped, marked as expected failures, or counted as passing.

The engineering suite exercises actual model/WASM readiness using synthetic silence, lifecycle, cache and UI behavior; navigation epochs, cooldown, complete-text negative/quote rejection and bounded audio buffers also remain mandatory unit tests. The real speech corpus and spoken-navigation test are acoustic benchmarks, not a claim of deterministic intent recognition. Run the manual benchmark after changing the model, vocabulary, capture/segmentation or parsing path and report every failure. Current known failures are two overlap clips, similar wake word 小弟, exact command replay, 别，小迪下一页 and 不是，小迪上一步. Engineering CI success does not mean these six failures or human/mobile/casting use have passed.
