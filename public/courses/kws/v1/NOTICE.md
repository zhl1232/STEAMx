# Course keyword spotting bundle

This directory contains the course-control runtime, not a general speech assistant. Audio is never cached or sent to a server. Static model/WASM files may be cached locally after an explicit start.

## Local modifications

`scripts/build-building-kws.sh` reproduces the runtime with a 64 MiB initial / 256 MiB maximum WASM heap, ES module factory, exported heap access, `SherpaOnnxDestroyOnlineStream` and `SherpaOnnxCreateKeywordStreamWithKeywords`. The upstream JS binding is adapted to export `createKws` and fixes `keywordsBufLen` to `keywordsBufSize` and adds per-stream keyword allocation/freeing, and requires an explicit configuration instead of the demo keyword defaults; it must stay paired with this C ABI. Only selected INT8 weights and tokens enter `.data` (original filenames within the embedded filesystem are preserved). The demo UI and ScriptProcessor implementation are not used.

`assets.js` records byte counts and SHA-256 for generated JS, WASM and model data. The worker checks WASM/data size and digest before initialization or accepting cached copies. Version the entire directory and cache name together for future model/runtime changes; no runtime CDN or external storage is involved.
