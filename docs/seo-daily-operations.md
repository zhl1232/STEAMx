# SEO / GEO 日常检查与专题运营

本手册维护操作节奏、故障处理和证据记录。品牌、标题、响应式入口、验证文件及推送范围只在 [索引清单](seo-indexing-checklist.md) 维护；本次文档整理未访问搜索后台或验证外链的最新内容。

## 首次设置与职责

明确运营记录负责人和开发排障负责人，按索引清单分别完成搜索平台验证与 sitemap 提交。三个 learn 专题承接积木、Scratch、科学兴趣，再链接真实课程/项目；无相应内容就不虚构条目。材料、步骤和安全信息按 [内容质量](content-quality.md) 维护。

## 每次发布的技术检查

在项目根目录使用 Node.js 22：

```sh
pnpm seo:check --base-url https://steam.bj.cn --report .tmp/seo-report.json
```

无依赖运行方式是 `node scripts/check-seo.mjs --base-url https://steam.bj.cn --report .tmp/seo-report.json`。它只发公开 GET、不提交 URL 或写数据库，报告写入指定本地文件。检查 robots、sitemap、首页、课程和专题，以及抽样详情的状态、元数据、正文和公开图片；不是全站扫描。

错误交开发处理，警告结合页面实际判断；标题和 H1 的验收标准见索引清单，不以脚本只警告为理由保留已不符合当前页面约定的结构。网络超时或外部图片限制与页面回归分开；脚本请求默认 8 秒并对临时网络/服务器故障最多重试一次，开发编译慢时先预热。

Release 在部署后、百度推送前运行相同检查，按 workflow 保存 JSON artifact。**检查失败不代表应用未部署，也不会自动回滚**；先查看具体响应与报告，再决定修复或经授权恢复。不要因一次网络波动反复改代码。

人工另查手机/桌面三个专题、代表积木/Scratch 课、禁用 JS 的课时正文、探索与自然列表的分页和错误状态。真实账号保存/续学不由公开检查替代；搜索后台索引也单独检查。

## 每日异常与每周效果

每日按实际权限查看技术可访问性、各搜索平台抓取/索引异常和新内容质量。没有后台权限就标记未核验；不以公开 GET 替代后台结果。本轮没有新增每日定时工作流。

每周固定窗口比较页面和查询词，建议最近 28 天对前 28 天；新站不足完整时间保留实际日期，不硬算完整环比。品牌词与非品牌词分开；保持平台、搜索类型、地区、语言、设备和页面过滤条件一致。

| 平台 | 记录方法与边界 |
|---|---|
| Google | 站点地图、网页索引、效果报告分开；按页面看查询，再按查询看落地页，记录展示/点击/CTR/平均排名及过滤条件 |
| 百度 | 索引量、抓取异常、推送结果、平台提供的流量/词数据分别记录；缺字段写 N/A，不套用其他平台字段，site 查询不当精确收录量 |
| Bing | 分别记录 sitemap、抓取错误、通知及效果；不因其他引擎恢复就关闭 Bing 的问题 |
| 生成式搜索 | 记录实际平台、日期、完整问题、地区/登录条件、可核验回答与引用；无法使用就写未核验，不将搜索排名或 llms.txt 存在当作 AI 推荐 |

低流量单日波动不直接触发标题改写，数据覆盖截止日期与检查时间分别记。公开搜索排名受地区和登录条件影响，不把单一地区或未登录浏览器结果当作所有目标地区的统一排名。

## sitemap 故障分层

| 层次 | 通过能证明什么 | 不能证明什么 |
|---|---|---|
| 公开 HTTP/XML 检查 | 当前响应和解析可用 | 搜索平台已经读取 |
| 实时网址测试 | 该次抓取成功 | 常规 sitemap 处理和内容页索引已成功 |
| 平台 sitemap 报告 | 对应读取/解析任务成功及发现数量 | 所有详情已收录或获得排名 |
| 具体页面索引 | 该 URL 的索引状态 | 其他 URL 同样已收录 |

先核对完整 sitemap URL，记录提交日期、上次读取、状态、发现数量和错误详情；空字段保留空，提交日期不能代替读取时间。列表/详情不一致则都记录。

实时测试失败时定位具体错误；实时测试成功而常规报告仍失败时，可在授权范围内重新提交一次并记录“实时通过，后台读取未确认”，不要不断重复提交。复查节奏只是内部约定，不是平台处理期限。

持续失败时核对相应时段源站/网关 `/sitemap.xml`、`/robots.txt` 日志及状态、耗时、DNS/TLS/拦截。无访问记录不能单独证明网络故障，User-Agent 也不能独立证明真实爬虫。以新成功的 sitemap 报告结束读取故障跟踪，具体内容收录继续单独跟踪；sitemap 本身不作为希望进入搜索结果的内容页反复请求索引。

当前实现的 sitemap 成功结果使用数据缓存并重验证；查询失败不能用只含静态 URL 的 200 掩盖。旧成功缓存是否跨部署存在取决于环境；数量骤减先查查询、状态和连通性，不伪造 URL 补数。lastmod 来自实际数据，不在每次请求写当前时间。

## 报表、隐私和变更

使用 [周报模板](seo-weekly-report-template.csv) 和 [sitemap 检查模板](seo-sitemap-check-template.csv)。记录版本/环境、日期、检查对象、条件、结果、证据和下一次核对项。未显示字段填空白/未提供，平台没有的功能填 N/A，仅见汇总时注明错误详情未展开。

不得把 token、验证码、会话 cookie、私有账号数据写入报表。旧截图和历史异常留作方法示例/历史证据，不作为当前结果；技术可抓取、提交、读取、索引、排名和生成式引用分别形成证据链。

内容维护以真实问题、材料、步骤、来源和课堂价值为主，不批量制造空泛专题，不承诺排名或 AI 引用。技术规则改动先更新索引清单及对应实现，运营流程改动更新本手册，未完成任务只在 [下一步](next-step.md) 追踪。
