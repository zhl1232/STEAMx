# 积木课程进度、作品奖励与 STEAM 结算

> 成长奖励修订为待上线代码，迁移未在生产执行；原课程闭环另有既有发布记录。

本文记录代码中的课程进度、作品奖励和 STEAM 雷达口径，不表示新迁移已上线。后续改动应先核对本文件、迁移和对应测试。

## 当前行为

- 课时完成写入 `user_lesson_progress`，不发 XP，也不再新增 `complete_lesson` 奖励流水；历史流水保留，不追扣、不冲正。
- 完成 API 在服务端校验登录、课程/课时关系、限流和 Scratch 必要校验后调用 service-role-only `record_course_lesson_completion`。重复请求幂等。
- 提交和安全审核不发成长 XP。项目/课时采用下述独立内容证据审核契约，替代原终稿 +20。
- 非空课程的当前课时全部以可信来源完成后，最多生成一条 `user_course_completions`。快照保存课时数、STEAM 权重和难度。
- STEAM 雷达只统计 approved final 项目、挑战完成、课程里程碑和 approved 且 `moderation_state='approved'` 的自然观察；自然观察固定按 3 星、`S:15` 计入科学维度。课程作品不额外作为项目贡献，雷达结果按稳定顺序计算。
- 登录用户获得批量计算的课程进度、下一课时和里程碑时间；匿名响应的 `progress` 为 null。`legacy_client` 完成记录可显示为历史已完成，但不会未经验证写入里程碑。

## 前台规则与权益展示

经验说明由 `lib/gamification/experience-rules.ts` 维护，应区分自然观察审核通过、项目/课时独立内容证据审核、新手任务领取及挑战审核/结算，不能承诺提交或点击完成即获得奖励。挑战保留现有不同路径：普通作品审核与限时挑战合格结算基础奖励为 20；长期挑战经项目审核完成时，反思与至少一次迭代可额外获得 10。不把不同路径写成可重复叠加领取。

成长体系弹窗使用 `lib/gamification/level-benefits.ts`，装扮门槛来自 `lib/shop/items.ts`，无门槛商品列入 Lv.1，经验门槛按等级公式计算。装扮是硬币兑换资格而非赠送；审核员等级仅为综合申请条件之一；推荐加权仅指已审核项目的推荐排序，不泛指所有作品或保证曝光。会员价格与折扣仍以商城专题为准。文案同步不代表奖励迁移已部署，发布状态仍以上述说明及目标数据库核验为准。

## 成长奖励契约（迁移后生效）

实现：`20261026100000_reviewed_growth_rewards.sql`、`20261026110000_growth_ai_review_queue.sql`、`lib/growth/`、项目问答与作品交流接口、管理后台安全页的「成长奖励复核」。项目问答恢复为独立区域，历史项目留言不改身份，导航改动不在此范围。

- 每日自动登录固定 **3 XP + 2 硬币**。上海日期、连续/累计登录天数保留，不再给连签档位或累计里程碑额外 XP。历史 XP/等级不追扣；等级仍为 `floor(sqrt(XP/100))+1`。
- 每用户、每项目或每课时最多 **200 XP**：首次真实过程 40、首次实质新观察/比较/调整 60、最终作品或总结 100，各阶段终身一次。课时 ID 优先作为课程作品的来源键，不能同时按项目与课时重复领取。失败也可以总结，文字探索记录也可用于最终总结，不强制三次提交。一份内容可以确认多个阶段。
- 复用现有 `completed_projects` 记录、安全审核和 DashScope 模型，不新增强制作业。模型读取有界背景、当前证据、回复对象和必要历史，分别返回发布安全与奖励资格；必须引用当前文本证据，不能按字数、图片数量或模型置信度打分。AI 只能判断内容证据，不能证明真的动手或答案科学正确；图片/视频为主且无可读证据的记录交人工。
- 项目问答与作品交流共享每天最多 **5 次，每次 5 XP**，**无周上限**；同用户同根问题/留言线程每天最多一次，按上海时区的首次审核发奖日期计数。问答根键为 `question_root_id`，作品交流沿父链找到根评论；两个入口的用户额度共用。不同真实问题不合并限制。作者回复他人可获，作品作者顶层自言自语、自回复、自动账号排除。
- 普通感谢、鼓励允许公开但无 XP；短而具体的问题也可符合条件；确定广告/恶意刷屏拒绝，价值不确定只暂缓奖励，安全不确定才待公开审核。规范化文本指纹跨入口保留防重复；匹配仍有效的已审核贡献时可跳过文本模型且不奖励新贡献，模型参考最近六条跨入口交流识别近重复/拆句；有限上下文不能保证识别所有改写刷分，举报与人工复核仍必要。
- 前台输入提示“有意义的提问、分享和建议，有机会获得经验奖励。” 当前版本符合质量标准显示“高质量回复”，即使额度已满也可显示；仅服务端账本确认实际 +5 才提示“高质量回复，获得 5 经验”。认可依据留在审核记录，不公开长解释；标签不是科学正确或官方背书。编辑/失效后旧标签隐藏。
- 作品赞/项目赞仍保留数字，不发 XP；旧作品被评论作者 +1 及相应扣分触发器关闭。撤销历史点赞/删除历史评论不会扣历史奖励。旧通用 RPC 的点赞、项目评论、评论周任务和最终 +20 路径均退役，不能与新奖励叠加。

### 审计、撤回与历史边界

`growth_reward_content` 在迁移后 INSERT 时登记新内容，不能靠改客户端日期让旧内容获奖。历史作品不批量补新奖励；切换前的待审记录也不会自动升级，继续实践可提交真实的新记录。每源已有 `complete_project` / `publish_course_work` 以及课程历史 `complete_lesson` 的正向流水保守计入 200 上限；历史最终奖励直接占用最终阶段，不补差额。无可归属来源的旧账不删除、不推测归属、不追扣；上线前须审计异常来源，必要时暂停相应账号/来源的人工奖励。

审核账本保留原文快照、内容哈希、审核人、依据、来源、实际 XP、纳入上限的旧 XP 和撤回时间。人工复核仅 moderator/admin，禁止自审。AI 通过 service-role-only 租约完成接口提交受校验结果，操作者记录为 system，审核人为空，不冒充管理员。浏览器不能写账本、质量标记或调用系统完成接口。审核时锁内容及用户资料行，额度检查与账本/XP 写入在同一事务；旧审核快照过期则拒绝。

`growth_reward_decisions` 独立追加每次成功的人工价值决定，保存审核人、内容版本和快照、阶段、依据及实际 XP 变动。重复拒奖、重复确认和额度已满时仍留记录，不受奖励身份去重影响；AI 完成和人工待办过滤均依据这份决定记录判断人工优先，不能只看是否新增了奖励流水。

人工复核选择「不奖励 / 撤回」可对仍然安全但不具价值的内容撤回奖励，撤回操作不要求内容/作品/父评论仍通过，也不因作者随后标记自动账号而被阻止。编辑实质内容、删除或失去通过状态时只撤回新账本对应奖励并记负流水；作品失去通过状态时撤回其下交流，父评论失去通过状态时撤回直接依赖它的回复。仍通过的父评论仅改文字不据此撤回回复。审核先锁作品和直接父评论、再锁评论与用户，和依赖驳回串行，避免并发漏撤。

**支持记录迭代和误审纠正**：一条记录先确认过程获得 40，补充实质比较后原证据需复核；审核员可同时重新确认过程（恢复原40）并首次确认发现（新增60），净收益为60。每个来源/阶段仍只有一个奖励身份，恢复不另建阶段或重算额度；重复恢复为0。所有首次确认、撤回和恢复写入只追加的 `growth_reward_events`，保留各版本快照、操作者、依据及金额；原始审核快照不覆盖。需要纠正部分阶段时，先撤回该条，再只确认真实成立的阶段，未确认阶段继续撤回。历史XP无新账本关联不受影响。

交流恢复沿用原审核日名额，不释放或另占名额；保留原文及每次恢复后的文本指纹，不能用编辑再恢复绕过去重。安全重新通过本身不会恢复价值奖励，必须再次独立内容证据审核确认。删除重建同来源的实践记录也只能在再次审核后恢复原阶段金额，不能重复增发；评论删除后重建不会凭新ID领回重复内容奖励。

账本快照包含用户内容，沿用管理员审核访问边界；未来隐私删除需独立匿名化流程，不能删除去重键重开发奖。管理页按作品记录、作品交流、项目问答读取安全通过内容（每页30条）并可撤回/恢复。另有 AI 异常与不确定队列（最近50条），可转入既有安全审核队列；安全通过后在成长复核中判断奖励。暂未提供批量操作。

### 自动队列与费用边界

新内容入队，现有 `after` 和定时 internal auto-interactions worker 驱动，无新外部调度服务。内容/依赖上下文哈希、租约和版本在完成事务中复核；变化则旧结果失效重新排队。模型超时、JSON 错误、无有效证据不发奖，最多三次任务尝试，再交人工。人工价值决定优先于此前排队的 AI 任务。

关联 Journey 的作品还将权威记录快照纳入上下文哈希。完成事务锁定并核对 Journey 记录与兼容作品的共享证据、来源及公开审核状态，防止两次同步请求之间的旧投影覆盖新编辑。发布安全拒绝或不确定时，在同一事务撤下两份记录、清空发布时间并撤回依赖奖励；终稿失效时重开原探索，并更新仍指向该次探索的旧入口。若已有新一轮 active 探索，安全撤下仍提交，新探索不变，旧探索保留历史完成元数据并以 `journey_reopen_conflict` 进入人工队列，等待处理状态冲突；该异常不由一次价值审核自动消除。

冲突任务由服务端保存原 Journey 身份。人工队列按当前状态判断是否仍需处理：原探索已重开、放弃或删除，或原探索的公开终稿与对应公开作品均重新通过且共享证据一致时，该任务退出待办列表。只恢复其中一份、仅做价值审核或解绑作品不算修复；无法确定原探索时保守保留。过滤在最近50条的限制之前执行，历史任务、错误和审核决定仍保留，读取队列不修改业务数据。

队列准入每天全站200次任务尝试、每人8次；每次文本审核最多两次实际模型调用、输出550 token、单次15秒。`usageObserver` 记录文本 token、调用状态与耗时；附图仍复用既有图片安全链，其费用独立，不计入这里的文本 token 日志。没有配置单价或货币预算，不能把准入限制说成完整费用预算保护。未进行真实付费模型批量评测，固定样例和结构化边界使用 mock，不能据此宣称真实模型准确率。

## 数据与权限基线

迁移 `supabase/migrations/20260731100000_course_progress_rewards_and_steam.sql` 创建/维护 `user_course_completions`、完成与 reconcile RPC、课程配置约束和雷达函数；后续奖励与雷达口径修订见同目录后续迁移。`lib/supabase/types.ts` 与迁移同步。

里程碑只允许本人读取（审核角色可读排障），普通客户端不能写入。完成、reconcile 和奖励结算均由服务端受控入口调用，RPC 固定 search path 并限制为 service role；不要把用户 ID 作为客户端可控参数转发。

课程配置必须有 S/T/E/A/M 五项有限非负权重且至少一项大于 0，难度为 1–6。非法配置修复前，完成仍保存进度并返回 `courseCompletionState='configuration_error'`，之后再由 reconcile 补结算。

## 维护入口

数据库连接、迁移模式、副作用及执行授权统一遵循 [数据库连接与迁移](database-psql.md)。下列维护命令须分别按其实际副作用和已批准范围执行；不能把命令名含 `status` 或 `dry-run` 当作只读依据。

每次课程结构、配置、审核奖励或雷达逻辑发布后运行：

```bash
pnpm db:status
pnpm db:course-config
pnpm course:audit
pnpm course:audit -- --json
```

`course:audit` 使用 pg-meta 查询做只读审计；默认阻断 P1 错误，`--strict` 会把历史 P2 advisory 也视为失败。当前已知的 3 条历史孤立 `complete_project` XP 流水保留，不删除、冲正或重发。

课程配置修复后先运行 `pnpm db:course-config`，再按单课程调用 service-role `reconcile_course_completions`。它只接受 approved 课程和可信完成来源，不会把 legacy 记录自动升级为能力来源，也不发 XP。

`repair_completion_rewards` 的旧 +20 apply 路径已关闭；dry-run 返回 retired。安全通过但未做成长审核不是漏发。旧审计的缺奖检查仅覆盖切换前记录，不对新记录自动补发。

## 关键接口契约

完成接口保留 `progress`、`alreadyCompleted`，并返回 `courseProgress` 与 `courseCompletionState`；状态固定为 `not_complete | created | already_recorded | configuration_error`。

`lib/api/courses.ts` 按批次读取课程、课时和当前用户进度，禁止逐课程 N+1；个性化响应使用 `private, no-store`。`lib/courses/progress.ts` 负责空课程、部分完成、全部完成和稳定下一课时的纯计算。

## 测试与发布检查

重点测试：`__tests__/api.courses-lesson-complete-route.test.ts`、`__tests__/api.completion-review-route.test.ts`、`lib/api/courses.test.ts`、课程进度纯函数测试和 `scripts/course-closure-audit.test.ts`。发布前确认：

- 首次/重复课时完成不产生 XP，Scratch 校验和匿名/登录进度隔离通过。
- 并发完成最后课时只生成一条里程碑；非法配置不回滚进度，修复后可补结算。
- pending 提交和安全审核不奖励；独立内容证据审核按上述阶段发放，重复/并发审核幂等。

- 普通 authenticated 不能直写里程碑；完成来源由 RPC 维护，legacy completion 不会自动固化为能力。

线上用 `pnpm course:audit -- --json` 采集配置错误、奖励 no-op/重复、里程碑缺口和 reconcile 延迟。回滚时切回应用读取或暂时移除雷达新来源，不删除里程碑、进度或历史 XP，也不恢复课时 XP。

### PC 与平板目录

- 768px 起采用顶部分类切换与下方课时网格。分类以真实课程为单位（小班积木、中班积木、大班积木、Scratch、棋类等），不混排三门积木课程的全部课时；默认选择第一门匹配课程。显式 `/courses?course=<id>` 优先于 `category` 和会话选择；没有显式课程时仍支持分类入口。分类使用真实链接，选择随地址导航完成后更新，避免点击时重复请求客户端目录；刷新、分享及浏览器前进后退保持选择，顶部仍允许切换其它课程。Scratch 分类按钮省略已知后缀「：从动画到作品」，不改课程原始名称或 SEO 元数据。
- 页面直接从分类开始，不显示手机横幅、标题旁的小插画、口号或「积木／编程／棋类」页内定位按钮。不新增搜索或课程介绍入口。
- 所选课程名称由上方选中标签展示，下方不重复显示标题，仅保留供屏幕阅读器识别区域的标题；展示真实适龄信息、课时数量与简短介绍。课时按原有稳定顺序展示为自适应网格，图片懒加载，点击直达课时。所选课程优先提供有效本机记录的「继续上次课时及页码」，没有本机记录时以真实在学状态提供简洁「继续学习」入口，不复用手机的大面积彩色卡片。
- 显式课程入口由服务端提供所选课程的全部轻量课时；普通入口先展示已有预览，预览不完整时读取所选课程的轻量目录，成功后展示全部课时，不使用横滑或每批追加。切换课程中止旧请求，旧响应不能覆盖当前选择；失败保留已有预览并给出重试，不将预览宣称为完整结果。只读取所选课程，不预先请求其它课程目录；完整目录及个人完成态仅在当前组件内存中使用，不持久缓存。
- 桌面宽屏最多六列；Scratch 使用 4:3 参考作品舞台预览，五子棋使用对应课时的真实棋局示意，积木沿用成品图。图片完整显示，编号位于角落、课名位于图片下方。没有可信预览的历史课时仍使用紧凑文字卡。Scratch 展示标题省略后缀，说明精简为「从动画、故事到小游戏，动手创作自己的作品。」，年龄、课时与陪伴要求合并一行；数据库原名与 SEO 标题保持不变。
- 桌面选择保存在既有 `courses:mobile-view:v1` 的 `desktopSelected` 字段中，不保存课时或个人进度；只有进入课时时更新共用 `selected` 返回标记。普通目录返回可恢复选择，明确的课程或分类深链接优先于已保存选择。

### 手机目录

- 保留插画横幅／继续学习入口、课程图标与标题，每门课程一行横向课时卡。课时数量只作普通文字，不提供「全部课时」、搜索、课程切换标签或介绍入口；横幅下提供「积木／编程／棋类」页内定位链接，只显示当前列表存在的类别，跳到该类第一门课程，不筛掉其他课程。有效 `category` 参数仍限定手机入口内容；显式 `course` 优先，自动定位对应课程横列，保存的纵向位置不能覆盖这次定位；课时返回仍恢复横列的已展开数量和横向位置。
- 顶部按课程横向显示所有在学课程的继续入口，每门一张，使用真实 `next_lesson`；无在学课程时保留插画横幅。暂未提供最近访问时间，不声称按最近访问排序。横幅是装饰插画与真实文本，不是课程成果或课程封面。
- 先显示现有预览，横滑接近末尾时按需读取该课程目录，每批追加 12 课；各横列末端也可点击加载，失败就地重试。图片懒加载，不预取课时页面。
- Scratch 与棋类没有独立预览图时，使用课名为主的浅色卡片，通用插图缩为小图标。小迪每会话一次的「想找哪节课？问我。」轻提示保持原行为，不自动发送消息。
- 手机仅在 sessionStorage 保存页面纵向位置、各课程横向位置与已显示数量、进入课时的课程 ID，不保存课时数据或个人进度；返回时按需重新读取目录并恢复位置。手机不展示顶部「技能课程」与通知铃铛行。

### 共用数据与返回边界

- 页面由服务端原有 `listApprovedCourses` 批量读取课程、预览及当前用户进度。服务端与首次客户端渲染保留真实课程标题、新目录链接和课时链接；显式课程入口包含该课程全部课时，普通入口保留已有课时预览，不能仅输出骨架；视口确定后切换到相应交互目录，不因此预读其它课程完整目录。分类根据已有名称/标签，Scratch 编程优先于实体积木识别，未识别类别进入「其他技能」，不能漏掉课程；积木按小班、中班、大班排列，其余保留同类原顺序。
- 只展示真实课时、进度及公开分级。未登录/未开始不虚构进度；没有分级则不编造难度或陪伴要求；图片失败沿用现有占位和重试。
- `GET /api/courses/[courseId]/catalog` 返回单门课程的 ID、稳定序号、标题、预览图和当前用户完成态，不读取工作区完整内容。`lib/courses/lesson-preview-image.ts` 统一列表、完整目录及服务端选择页的图片映射，只增加课程类型与 Scratch 课程/课时键、小游戏键的轻量投影。复用已审核／上架／分级访问规则，响应为 `private, no-store`；离开页面取消未完成请求，不写完成状态。
- 各端课时返回、面包屑、完成弹层、分享和证书入口统一使用 `/courses?course=<id>`。课程目录承接精简介绍、分享、继续学习和结课证书入口，不再增加课程介绍中间页。
- 目录展示文案由 `course-presentation.ts` 统一精简：「五子棋博弈论入门」简称「五子棋」，简介只说明学习内容，不重复年龄、课数及课程名；源标题与 SEO 保留完整身份。桌面简介使用操作区之外的可用宽度，仅在空间不足时自然换行。

对应回归：`components/features/courses/course-board.test.tsx`、`course-hub-mobile.test.tsx`、`desktop-course-catalog.test.tsx`、`use-course-return-href.test.tsx`，检查真实课时链接、分类入口、完整目录、请求切换与重试、手机按需加载和返回路径。修改目录展示不应执行数据库命令或触发生产部署。

### 课程中间页退役与访问边界

- 删除 `/courses/[courseId]` 页面，不为旧链接设置跳转；旧根地址返回 404。课时、材料、预览、证书子路由及课程 API 保留，数据库、学习进度与作品不变。
- 已审核但未上架的历史课程仅在显式课程地址访问，输出 `noindex, follow`，不加入普通分类、推荐和 sitemap；仍显示有效新版课程入口。草稿、不存在或不可访问的课程不能通过查询参数绕过访问限制。
- 参数只接受单个规范正整数 ID；无效或重复参数进入未找到状态。数据库读取失败提供重试，不伪装成课程不存在。
- 上架课程的标题、描述、canonical、结构化数据和 sitemap 使用一致的新目录地址；搜索与 GEO 规则见 [SEO 索引清单](seo-indexing-checklist.md)。

### 预览资源维护

- 静态预览位于 `public/assets/course-previews/`，随应用交付，不经过 `/courses/` 的 OSS 路径重写。目录只加载小图片，不运行 Scratch VM。
- Scratch：本地开发服务启动后运行 `node scripts/scratch-curriculum/render-previews.mjs`，从 48 个原始参考 SB3 的真实舞台渲染生成 WebP。只为 `scratch-original-v1` 的有效课时键映射，不用通用猫图代替作品。
- 五子棋：`node scripts/render-gomoku-course-previews.mjs` 使用匿名客户端只读查询已上架课程，提取每课首个含棋子的真实示意，生成 SVG 与 `lib/courses/gomoku-previews.json` 标题映射；不写数据库。课时改名或棋局更新时同步再生成。
