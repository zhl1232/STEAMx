## 一、挑战层的使用规则

以下情况优先进入挑战层，而不是继续保留在项目层：

- 目标不是学一个小技能，而是完成一个综合任务
- 需要多阶段推进
- 需要多次试错、优化或对比
- 用户最终要提交一个完整方案、作品或报告
- 适合排行榜、展示墙或长期迭代

这类内容应充分使用挑战系统已有字段：

- `scenario`
- `driving_question`
- `expected_outcome`
- `constraints`
- `stages`

## 三、每个挑战的推荐 PBL 骨架

### 1. 机器人迷宫闯关挑战

- `scenario`：一台小车需要在复杂路径中自主或半自主完成闯关
- `driving_question`：怎样同时提升小车的路径判断、稳定性和通关效率
- `expected_outcome`：一台可运行的小车 + 调试记录 + 通关演示
- `stages`：
  1. 搭建底盘与驱动
  2. 测试转向与避障
  3. 反复调参优化
  4. 完成迷宫实测

### 2. 仿生结构创意挑战

- `scenario`：自然界中很多结构兼具轻量和强度，值得模仿
- `driving_question`：如何把自然结构转化为可制作、可解释的人工结构
- `expected_outcome`：一个仿生结构样件 + 结构说明
- `stages`：
  1. 观察自然原型
  2. 抽取结构规律
  3. 制作并测试样件
  4. 总结优缺点

### 3. 连锁机关创作挑战

- `scenario`：用连续动作完成一个看似简单的小目标
- `driving_question`：如何让多个环节稳定衔接而不失效
- `expected_outcome`：一套完整连锁机关视频或现场演示
- `stages`：
  1. 设计动作链
  2. 制作单个模块
  3. 连接并调试模块
  4. 完成整机演示

### 4. 纸杯高塔稳定挑战

- `scenario`：用极简单的材料搭出高度和稳定性兼顾的结构
- `driving_question`：什么样的堆叠方式最稳，为什么
- `expected_outcome`：高塔照片 / 视频 + 堆叠策略说明
- `stages`：
  1. 测试基础堆法
  2. 选择稳定结构
  3. 提升高度
  4. 完成终测

### 5. 轻量承重桥挑战

- `scenario`：桥梁材料有限，但承重要尽可能高
- `driving_question`：如何在重量、结构和承载之间取得最好平衡
- `expected_outcome`：桥梁作品 + 承重测试结果
- `stages`：
  1. 选定桥型
  2. 制作初版桥梁
  3. 记录承重失效点
  4. 优化后复测

### 6. 大跨度桥梁方案挑战

- `scenario`：需要跨越更大的空间，但材料和结构稳定性都面临压力
- `driving_question`：什么样的桥型更适合大跨度场景
- `expected_outcome`：结构方案图 + 模型或仿真结果
- `stages`：
  1. 明确跨度目标
  2. 比较桥型
  3. 制作样件或仿真
  4. 输出方案说明

### 7. 远距弹射器挑战

- `scenario`：在规则限定下实现更远或更准确的发射
- `driving_question`：弹射距离与稳定性受哪些因素影响
- `expected_outcome`：弹射器作品 + 发射测试数据
- `stages`：
  1. 搭建基础弹射器
  2. 修改角度与结构
  3. 记录测试数据
  4. 确认最佳参数

### 8. 未来社区规划挑战

- `scenario`：围绕真实生活需求规划一个更适合居住的社区
- `driving_question`：怎样平衡功能、交通、公共活动和生态空间
- `expected_outcome`：社区沙盘或平面方案 + 规划说明
- `stages`：
  1. 设定社区需求
  2. 划分功能区域
  3. 制作沙盘
  4. 说明规划逻辑

### 9. 纸板公共装置挑战

- `scenario`：设计一件能在公共空间展示的装置作品
- `driving_question`：如何让装置兼顾视觉冲击、结构安全和互动性
- `expected_outcome`：装置作品 + 展示说明
- `stages`：
  1. 设定主题
  2. 设计尺度和结构
  3. 制作装置
  4. 完成展示记录

### 10. 密码解谜挑战

- `scenario`：信息被编码，需要通过规则理解和推理完成破解或设计
- `driving_question`：不同加密规则分别适合制造什么样的谜题体验
- `expected_outcome`：一组谜题或破解过程记录
- `stages`：
  1. 学习一种编码规则
  2. 设计或破解样题
  3. 增加复杂度
  4. 完成整组谜题

### 11. 桌游胜率分析挑战

- `scenario`：桌游策略看似靠经验，实际上可以被量化分析
- `driving_question`：哪种策略在给定规则下更有优势，为什么
- `expected_outcome`：策略分析图表 + 结论说明
- `stages`：
  1. 选择桌游
  2. 定义策略变量
  3. 收集对局数据
  4. 形成分析结论

### 12. 小型抽样调查挑战

- `scenario`：想知道一个真实问题的情况，但不能对所有人做全量调查
- `driving_question`：怎样设计样本，才能让结果更有代表性
- `expected_outcome`：调查问卷 + 数据图表 + 简短结论
- `stages`：
  1. 确定问题
  2. 设计抽样方式
  3. 收集和清理数据
  4. 输出结论

### 13. 生活问题建模挑战

- `scenario`：现实世界的问题往往可以被简化成变量和关系
- `driving_question`：怎样把生活问题转化成可计算、可解释的模型
- `expected_outcome`：模型说明 + 简化假设 + 结果展示
- `stages`：
  1. 选定生活问题
  2. 明确变量和假设
  3. 建立关系式
  4. 解释模型结果

### 14. 汉诺塔规则闯关挑战

- `scenario`：在有限规则下，以尽可能高效的方式移动圆盘
- `driving_question`：最优解为什么成立，怎样把策略变成可操作步骤
- `expected_outcome`：汉诺塔装置 + 闯关记录
- `stages`：
  1. 制作装置
  2. 理解基本规则
  3. 按层数练习
  4. 完成计时挑战

### 15. 密室谜题设计挑战

- `scenario`：要让玩家通过线索、机关和推理逐步完成逃脱
- `driving_question`：怎样让谜题既有挑战性又能被真实玩家解开
- `expected_outcome`：一套可试玩谜题 + 测试反馈记录
- `stages`：
  1. 设计主题故事
  2. 设计线索链路
  3. 制作谜题或机关
  4. 试玩并迭代

## 四、这些挑战与项目层的关系

这些挑战不应再被视为单独项目，但可以聚合多个项目作为脚手架。

例如：

- `机器人迷宫闯关挑战` 可关联：`Arduino 巡线小车`、`避障机器人`
- `轻量承重桥挑战` 可关联：`纸张折叠桥`、`冰棍棒桁架桥`
- `远距弹射器挑战` 可关联：`杠杆投石机`
- `未来社区规划挑战` 可关联：`纸板小房子`、`建筑沙盘`
- `密室谜题设计挑战` 可关联：`逻辑电路与门`、`流程图设计`

规则应该是：

- 项目负责局部技能
- 挑战负责整合目标
