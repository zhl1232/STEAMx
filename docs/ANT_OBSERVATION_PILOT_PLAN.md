# 蚂蚁观察挑战落地方案

## 一、文档目标

这份方案把“观察蚂蚁”从一个点子整理成当前平台可直接上线的第一期自然观察挑战，目标是先跑通：

- 一个可长期开放的蚂蚁观察挑战
- 三个适合作为 starter task 的观察项目
- 一套适合中小学生的多日观察记录口径
- 一份对“高解释性行为”保持谨慎的观察规则

当前建议沿用现有 `Challenge + Project` 结构，不额外发明新产品形态。

原因很直接：

- 蚂蚁观察天然适合做多日、可迭代的作品
- 当前 evergreen challenge 已支持同一用户持续编辑一份挑战作品
- 这正好匹配“连续 14 天记录”的任务形态

## 二、为什么先做蚂蚁观察

### 1. 低门槛

- 家里、小区、校园、公园都容易找到观察点
- 不依赖望远镜等专门装备
- 适合短时、多次、重复到达

### 2. 容易出现“多天才看得出来”的变化

蚂蚁不是那种看 3 分钟就结束的对象。真正有意思的地方，往往来自连续观察：

- 同一个洞口在不同天气下活跃程度不同
- 同一条路线会在几天内越来越稳定
- 搬运、打洞、清理、警戒可能在不同时间出现
- 某些复杂互动像“救同伴”，但需要更多证据才能判断

### 3. 适合训练“事实”和“解释”分离

蚂蚁行为很容易被拟人化，因此这个挑战特别适合训练参与者：

- 先写看到什么
- 再写自己怎么理解
- 对高解释性结论保留不确定性

## 三、第一期挑战草案

这一部分可以直接映射到当前挑战字段。

### 1. 挑战标题

`14天蚂蚁观察挑战`

### 2. 挑战定位

让参与者在家里、小区或校园附近找到一个固定蚂蚁活动点，连续 14 天记录蚂蚁的路线、搬运、挖掘和同伴互动，把零散观察整理成一份有证据的行为日志。

### 3. 建议字段映射

| 字段 | 建议内容 |
|---|---|
| `title` | 14天蚂蚁观察挑战 |
| `challenge_type` | `evergreen` |
| `description` | 面向初学者的多日自然观察活动，重点是连续记录，而不是一次性打卡。 |
| `tags` | `["蚂蚁", "自然观察", "昆虫", "动物观察", "多日观察"]` |
| `difficulty_stars` | `2` |
| `scenario` | 你可能每天都见过蚂蚁，却很少真的停下来连续观察它们。只要连续看上几天，就会发现同一个活动点在不同条件下会出现不同节奏。 |
| `driving_question` | 如果我们连续 14 天在同一个地点观察蚂蚁，能否识别出稳定行为模式，并区分“看到的事实”和“自己的猜想”？ |
| `expected_outcome` | 形成包含连续日志、行为分类、照片/视频证据和反思的完整作品。 |
| `constraints` | 见下方注意事项 |

### 4. 为什么用 `evergreen`

不建议把这个挑战做成单纯的限时活动页。

更合适的做法是：

- 用 `evergreen` 承载长期开放的学习挑战
- 把“14 天”定义为参与者自己的观察周期
- 允许参与者在挑战期间持续编辑和完善同一份作品

这比一次性提交更符合自然观察的真实节奏。

### 5. 建议活动阶段

| 阶段标题 | 描述 | `hint` 建议 |
|---|---|---|
| 找到固定观察点 | 在家里、小区或校园附近找到一个能连续到达的蚂蚁活动点。 | 优先选同一个洞口、墙角路线或树下蚁道。 |
| 连续观察 14 天 | 每天在相近时间观察 10 到 20 分钟。 | 尽量保持同样的时间和站位，便于比较。 |
| 区分行为与猜想 | 把打洞、搬运、触角接触、拖拽、警戒等现象分开记录。 | 先写事实，再写猜想。 |
| 整理证据并提交 | 从日志里整理出最有代表性的证据。 | 优先提交能说明变化过程的记录，而不是单张照片。 |

## 四、行为记录口径

这是这个挑战最关键的部分。平台不应该鼓励用户一上来就下结论，而应该先给出清晰的记录口径。

### 1. 推荐的行为分类

#### 基础行为

- 排队行进
- 进出巢穴
- 搬运食物
- 触角接触

#### 进阶行为

- 打洞或清理洞口
- 拖动较大食物
- 清理碎屑或尸体
- 多只个体协同搬运

#### 高解释性行为

- 拖拽受伤或不动的同伴
- 搬运幼体
- 疑似救援
- 疑似分工或警戒轮换

### 2. 对“救同伴”这类现象的处理原则

这个点必须写清楚，否则很容易把挑战带偏。

推荐规则：

- 可以记录“疑似救援”或“疑似拖拽同伴”
- 不能要求参与者直接断言“蚂蚁会救同伴”
- 必须同时写下客观事实，例如距离、持续时间、前后发生了什么
- 最好附短视频，而不是只凭一句描述
- 如果证据不足，应该鼓励写“待确认”

建议在评分和示例文案里都强调：

**谨慎记录不确定性，比过度解释更有科学价值。**

### 3. 推荐日志模板字段

- 日期
- 时间
- 地点
- 天气
- 活跃程度
- 观察到的行为
- 证据类型（照片/视频/草图）
- 事实描述
- 我的猜想
- 还不确定的问题

## 五、第一期 starter 项目

这些项目适合直接挂在挑战下，作为推荐任务。

### 项目 A：固定蚁巢口 7 天观察

适合第一次参与的用户，目标是先建立连续记录习惯。

建议重点：

- 固定地点
- 固定时间
- 一周日志
- 对比每天变化

### 项目 B：蚂蚁搬运路线与食物选择

把观察重点放到觅食和搬运行为上。

建议重点：

- 先看天然路线
- 如需设置食物，只能少量、安全、远离巢口
- 记录发现食物和同伴到来的时间差
- 画路线草图

### 项目 C：连续行为观察：打洞、搬运与同伴互动

把挑战推进到真正的行为观察层。

建议重点：

- 连续多次记录
- 行为分类
- 对复杂互动保留不确定性
- 整理成 3 到 5 条代表性证据

## 六、提交与评分建议

### 1. 提交要求

- 至少连续记录 7 天，完成版目标为 14 天
- 至少提交 3 条带证据的行为记录
- 至少写出 1 条“我最确定的现象”
- 至少写出 1 条“我还不确定的问题”

### 2. 评分建议

推荐综合打分：

- 持续性与完整度 40%
- 行为多样性 35%
- 科学性与反思 25%

### 3. 什么是高质量作品

高质量作品不等于“发现了最罕见的行为”。

更合理的标准是：

- 记录连续
- 证据清楚
- 区分事实和猜想
- 能指出自己还没搞明白的地方

## 七、安全与伦理

这个挑战必须明确反对破坏性观察。

建议直接写入规则：

- 不挖开蚁巢
- 不灌水、不烟熏、不堵洞
- 不捕捉和长期圈养蚂蚁
- 不使用有毒食物或化学品
- 不为了“制造现象”反复干扰路线

如果要做第一期上线，建议默认把“自然环境定点观察”作为主方法，而不是人工搭建蚂蚁巢。

## 八、当前落地结论

当前平台第一期最合适的实现方式是：

1. 创建一个 `evergreen` 的 `14天蚂蚁观察挑战`
2. 挂 3 个 starter 项目
3. 用项目与挑战文案统一行为记录口径
4. 先用 `Challenge + Project` 跑通多日观察提交流程

后续如果蚂蚁、鸟类、植物等自然观察内容都要扩展，再统一进入 `Observation Event + Species` 层的深化建设。
