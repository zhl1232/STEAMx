## 一、V2 的命名原则

项目标题不再使用“大主题”命名，而改成“动作 + 对象 + 小产出”。

优先满足这三个条件：

1. 用户一眼能看懂自己要做什么
2. 用户能推断出这是一次短周期任务，而不是长期主题
3. 标题本身就能和挑战、观察专题拉开层级

### 建议保留的命名结构

- `用某种方法完成一个小实验`
- `制作一个明确的小作品`
- `比较两个对象的一个特征`
- `记录一次可量化的现象`
- `搭建一个具体的小装置`

### 建议避免的命名结构

- `观察……`
- `……日记`
- `……记录`
- `……图鉴`
- `……调查`
- `……研究`
- `……分析`
- `……入门`
- `……设计`

除非标题后半句已经把动作和产物说得足够具体，否则这些词会让项目重新变回泛主题。

## 三、V2 命名后的结构变化

这 31 个项目改完后，项目层会更接近“技能卡”而不是“主题页”。

变化主要体现在：

- 从 `长期任务` 改成 `单次完成`
- 从 `大范围主题` 改成 `局部动作`
- 从 `开放式命题` 改成 `可交付的小产物`
- 从 `学科名词` 改成 `实际操作`

## 四、这一版还保留的取舍

V2 不是所有项目都强行压成超短标题，而是保留了必要的学科信息。

例如：

- `双桥型受力仿真对比` 仍然保留了“仿真”和“对比”
- `双轮自平衡小车调试` 仍然保留了“自平衡”
- `旅行商路线谜题` 仍然保留了原问题的核心概念

这样做的目的，是避免标题虽然更具体，但把学科价值也一起削掉。

## 五、建议下一步

完成这 31 个标题定稿后，建议继续做两件事：

1. 对 15 个“应上移为挑战”的条目出一版挑战名称与挑战摘要
2. 对 23 个“应移出项目层”的条目出一版观察域结构稿

这样三层内容会同时闭合：

- 项目层有明确小技能标题
- 挑战层有真正的 PBL 任务
- 观察层有独立的长期记录逻辑
