## 首期范围

- 一笔订单购买一种规格，可调整数量；不做跨商品购物车、拆单和部分退款；会员权益和手动发券规则见下文。
- 每商品配置固定每单运费和不配送省份，仅中国大陆。上架前必须配置运费、售价、可售数量及履约说明。
- 地址加密，供货链接、采购成本、密钥不进入公开商品或订单响应。
- 数据库事务计算价格并保存快照，同时锁定可售库存。待付款有效期 30 分钟；已发起支付的订单只有确认渠道关单后才能释放库存。
- 验签并核对商户、订单、金额和币种后才能确认支付。支付成功创建唯一人工采购任务，管理员到供应商下单并回填采购单号和成本。
- 供应商代发，管理员回填一个包裹的承运商及物流单号，不启用 1688 自动下单。
- 买家申请整单售后，管理员审核后直接退款或要求退货；退款包括原支付运费，原路退回，渠道确认后才标记退款成功。退款不会自动恢复库存，需人工复核供应商库存。

## 现金商城会员权益与优惠券

普通或过期会员商品原价；有效普通会员商品 8.8 折、有效创始会员商品 8 折，按整单商品小计四舍五入到分。运费全价，管理员角色本身不产生会员权益。会员资格遵循 `lib/membership.ts`；订单创建后保存价格快照，30 分钟付款窗口内不随会员过期重新定价。

`POST /api/store/quote` 在服务端计算原商品额、会员商品额、会员减免、券减免、硬币抵扣及现金实付。创建订单必须携带该 `expectedQuote` 和明确的 `couponId` / `useCoins` 选择；重算不同返回 `409 QUOTE_CHANGED`，需重新确认。相同用户及幂等键已创建订单的重试直接返回原单，不重新定价。`GET /api/store/orders?intent=<key>` 仅查询当前用户的该购买意图，供超时或刷新后恢复；浏览器只保存意图键、优惠选择和已创建订单 ID，不保存地址。进入一次新购买生成新意图，重试沿用原键；网络未知时不会自动改价再提交。

有效会员可以主动选择硬币抵扣：100 硬币抵 1 元（每硬币 1 分），上限为会员价商品额的 10% 向下取整，受可用硬币余额限制；不抵运费。硬币与优惠券二选一，默认均不选。数据库在同一事务锁库存、重算价格、预扣硬币及创建唯一订单权益预留；支付确认仅消费预留，不二次扣币。安全取消（支付尝试已确认关闭）和渠道验证整单退款只返还一次原硬币。

优惠券只向有效创始会员手动批量发放，使用时也要求有效创始会员。后台模板配置面额、会员价商品额门槛、适用商品、有效天数、条款及激活状态；预置“满50减5”仅为未激活草稿，不自动发行。发放由管理员选择账号并确认批次，人数即张数，每批每人一张，批次幂等键防重试重复发放；不自动按月发券、不修改会员资格。已发券的条款、门槛、面额、适用商品和原到期时间不可改写。订单一次只用一张券，面额严格小于会员价商品额，保持正现金支付；创建占用、付款核销，安全取消及验证整单退款恢复原券且保留原到期时间，过期券不会因此延期。

订单公开金额字段明确区分 `original_subtotal_cents`、`member_subtotal_cents`、`member_discount_cents`、`coupon_discount_cents`、`coin_discount_cents`、`coins_used` 和现金实付 `total_cents`。历史订单零优惠兼容。`store_coin_holds`、`store_benefit_ledger` 及 `coin_logs` 保留预扣和归还证据；权益表仅服务端访问。订单创建时另存不可变私密采购快照，包含供应商链接、成本、规格和来源资料，仅后台订单详情可读；公开商品和订单响应不返回这些资料。

商品可以配置图库、详情文字、视频和分类。草稿允许暂缺运费、有限库存、采购链接/成本和履约说明，上架时必须补齐；并发版本保护继续适用。支付渠道列表仅反映服务端开关；本地已允许创建真实订单，真实收款还需商户参数及回调配置。

实现入口：`lib/store/native.ts`、`lib/store/benefit-input.ts`、`app/api/store/quote/`、`app/api/store/coupons/`、`app/api/admin/store/coupons/`、`20261026140000_store_member_benefits.sql`。此批迁移已在上述真实实例执行；这不代表应用已发布或真实支付已验收。

## 硬币商城

`/shop` 的装扮兑换取消原等级 30 的八折逻辑，改用上节相同的有效会员身份和折扣比例。硬币价格向下取整、最低 1 枚，等级仅继续控制个别装扮的解锁资格。`get_shop_prices()` 批量返回权威价格、等级、余额与已拥有状态，展示、余额判断和 `purchase_item(item, expectedPrice)` 使用同一 SQL 计价函数。新双参数入口遇到价格变化必须确认后再次兑换；旧单参数入口为尚未更新的客户端保留兼容，在资料行锁下计算当前会员价并共用扣款实现，实际金额不高于旧页面显示的基础价。`/coins` 目标排除已拥有及尚未解锁的装扮，显示会员实际价格。

兑换与实物订单预扣使用同一 `profiles.coins` 可用余额，并在事务中锁行、记流水。投币双方与批量奖励按 UUID 顺序锁用户资料，避免相反锁序；挑战结算事务及历史异常保护见 [PBL 指南](PBL_CHALLENGE_GUIDE.md)。这些 SQL 由 `20261026130000_shop_membership_and_atomic_challenge.sql` 提供。

## 本地素材草稿与页面

站内路径为 `/store` 目录、`/store/products/[id]` 详情、`/store/checkout` 结算和 `/store/orders` 订单。商品及订单客服入口进入独立 [官方客服](customer-support.md)，普通私信保持原有边界。

线上测试期间，顶部导航、头像菜单及个人中心隐藏实物商城目录入口，直接访问 `/store` 仍遵循目录开关。个人中心原 `/shop` 入口明确命名为「硬币商城」并继续保留。订单和客服入口独立保留；目录关闭时订单空状态引导继续学习。手机底栏不新增商城频道。

`GET /api/store/availability` 只返回运行时 `catalogVisible`，不读取数据库或暴露支付配置，响应禁止缓存。根布局的 `StoreAvailabilityProvider` 共享这一结果，订单空状态据此判断能否引导浏览目录；菜单不因目录开启而展示商城。请求失败按目录不可用处理，每分钟内复用查询、过期后聚焦重查，无定时轮询或页面刷新。导航可见性不代替服务端路由、鉴权与购买开关校验。页面接入不代表商品上架或真实支付已完成。

`data/store/source-drafts.json` 和 `20261026160000_store_source_drafts.sql` 保存来自本地仓库包的两个科学实验商品、18 个原规格的待审草稿。迁移仅首次插入草稿和暂停规格，库存为零、运费/成本/货源映射待确认；重跑不覆盖人工编辑。不会把原仓库大库存、48 小时发货或 1688 候选截图直接当作履约承诺。

上述两个商品和规格已写入真实数据库，仍保留草稿、暂停规格和零库存。`/admin/store` 从数据库读取并保存商品；每项「查看商品页面」进入 `/admin/store/products/[id]/preview`，服务端先验证管理员身份，再读取白名单展示字段。预览显示真实草稿与暂停规格，未确认运费/库存如实标注，关闭购买并使用通用客服入口，不返回采购成本或供应商资料。返回编辑时通过 `?product=<id>` 定位对应商品。

`/admin/store/source-drafts` 仅在 development 且管理员登录后读取静态来源资料，用于比对图片、规格、原价与待确认项，不代替真实数据库预览。三张保留图片为原图字节拷贝；两条原仓库商品共用同组图片，不能据图判断各规格包装。厂家/OEM、赠品、视频承诺、买家秀和未证实的 AI 素材没有采用；1688 的实验数量与仓库记录存在差异，待负责人确认，不自动合并规格。供货候选和审核备注只在管理资料中，不进入公开商品响应。尚无真实积木商品素材。

## 支付实现约束

支付宝使用官方 `alipay-sdk`，桌面网页支付和手机网页支付；微信使用 API v3 的 Native 二维码与 H5。微信内置浏览器提示用外部浏览器打开，本期不做 JSAPI、OAuth 或小程序支付。

微信实现参考 wxstack 的公开代码，必须保留来源和许可证记录。其原有响应验签不能直接作为交易信任边界：缺少签名、未知公钥编号、验签失败均应拒绝，异步验签必须等待完成。商户私钥签名、平台公钥验签和 API v3 密钥解密分别处理。

每个订单只允许一个活动支付尝试；切换通道前关闭旧尝试。网络超时保留未知状态，使用相同商户订单号查单，不另建号码猜测失败。退款同样使用稳定退款号并查询确认。页面跳转结果、浏览器传入金额、旧 HMAC webhook 均不能修改支付结果。

旧 `/api/store/payments/webhook` 永久返回 410。支付宝和微信分别使用渠道专属回调。回调及服务端查询仍可处理既有交易，不因关闭新购开关而丢失在途订单。

## 配置与隔离

开关均默认关闭，目录展示、新建订单和真实支付互相独立：

- `STORE_CATALOG_ENABLED`：公开目录。
- 关闭目录时目录、商品详情和结算返回 404，父 layout 不拦截订单与售后；关闭页标题为“页面未找到”，开启时为“材料包商城”，两者保持 noindex。`/store/orders` 及详情独立使用“本站材料包订单”标题，仍要求原有登录与订单访问权限。
- `STORE_CHECKOUT_ENABLED`：新建订单，仍需目录开关。
- `STORE_PAYMENTS_ENABLED`：发起支付总开关。
- `STORE_ALIPAY_ENABLED`、`STORE_WECHAT_ENABLED`：单通道发起支付开关。
- `STORE_ADMIN_PREVIEW_ENABLED`：管理员测试预览，还必须满足非生产、`STORE_ENVIRONMENT=test` 和本地 Supabase 地址。
- `STORE_ALIBABA_AUTOMATION_ENABLED`：旧自动采购路径，保持关闭。

完整配置见 `.env.example`。凭证只设在服务端，不能使用 `NEXT_PUBLIC_` 前缀。公共商品入口目前默认隐藏，后续开放时需统一复核界面入口及服务端开关。

支付宝可使用官方沙箱，前提是配置真实沙箱应用密钥；未配置时只做本地测试。微信不假称存在官方交易沙箱，准入前使用生成的签名/加密测试夹具和模拟传输验证协议。

## 验收和开放顺序

1. 每次应用迁移前审核所有待执行项并确认目标环境；获得该环境写入授权后使用 `pnpm db:push`。禁止使用 `supabase db push`。`db:status` 和 `--dry-run` 会初始化追踪表，不能当成只读检查。
2. 配置真实商品、变体、运费、禁配地区、供货渠道和有限库存；复核课程关联。
3. 在隔离数据库完成并发库存、重复通知、金额篡改、关单支付竞态、退款超时和权限隔离测试。
4. 完成商户产品审核，配置 HTTPS 回调、服务端密钥、对账任务及运维告警。
5. 在获得真实交易测试授权后验证小额支付、关单、人工采购、物流、整单退款闭环。
6. 最后再启用公开入口及购买开关。代码测试通过不能替代通道联调与运营验收。

历史淘宝订单的支付、物流与售后仍在淘宝处理；本站不会导入或伪造这些外部交易状态。

- 支付尝试使用库存预留的绝对截止时间。渠道确认关单可取消；仅当已过截止时间及两分钟缓冲、且验签后的渠道查单明确表示订单不存在时，才释放尚未在渠道建立的订单。网络错误、普通 404 和验签失败均不能代替这一证据。首次真实联调需验证过期链接不可支付。
- 微信公钥模式发送 `Wechatpay-Serial` 选择平台公钥。此实现仅配置单套平台公钥，已有商户从证书切换时必须先完成微信侧迁移，确认回调已采用该公钥；不要在旧证书回调仍在途时直接切换。
