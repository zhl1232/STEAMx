## 一、观察域的重新定义

观察域不再被视为“另一种项目列表”，而是一套独立内容结构。

建议拆成四类内容：

1. `观察主题（Observation Theme）`
2. `观察挑战（Observation Challenge）`
3. `物种 / 对象页（Species / Subject）`
4. `观察方法卡（Observation Skill）`

### 1. 观察主题

适合承载：

- 一类持续观察对象
- 一种典型观察情境
- 一个长期可进入的观察入口

例如：

- 校园常见鸟类
- 月相变化
- 云层与天气
- 蝴蝶生命周期

### 2. 观察挑战

适合承载：

- 多天或多次观察
- 需要完成记录、整理和总结
- 有阶段目标和最终成果

例如：

- 7 天宠物行为记录挑战
- 春季迁徙观察挑战
- 校园植物多样性观察挑战

### 3. 物种 / 对象页

适合承载：

- 某个可被识别的物种或对象
- 识别特征
- 常见环境
- 最近观察记录

例如：

- 白头鹎
- 绿豆幼苗
- 月亮
- 卷云

### 4. 观察方法卡

这是唯一保留在“技能型内容”里的观察相关内容，但它不是项目。

适合承载：

- 如何填写观察记录
- 如何识别行为类型
- 如何选择观察点
- 如何避免干扰生物

## 三、迁移后的页面职责建议

### A. 观察主题页

适合放这些模块：

- 主题简介
- 推荐观察时间
- 推荐地点类型
- 常见对象 / 物种卡片
- 最近公开观察记录
- 相关观察挑战
- 相关观察方法卡

适合归入这一页的条目包括：

- 常见喂鸟点观察
- 小区常见鸟类图鉴
- 蚂蚁群体行为观察
- 蜘蛛结网行为观察
- 月相变化观察
- 季节星座观察

### B. 观察挑战页

适合放这些模块：

- 挑战时间跨度
- 记录要求
- 建议观察频率
- 提交模板
- 示例记录
- 阶段目标
- 总结产出

适合归入这一页的条目包括：

- 蚂蚁路线追踪挑战
- 7 天宠物行为记录挑战
- 春季迁徙鸟类观察挑战
- 潮间带生物记录挑战
- 本地鸟类多样性挑战
- 一周气象观测挑战
- 地质徒步观察挑战

### C. 物种 / 对象页

这类条目不一定直接由本轮 23 个标题生成，但迁移后要能链接到对应对象页。

例如：

- `小区常见鸟类图鉴` 应继续下钻到具体鸟种页
- `常见野花图鉴` 应继续下钻到具体花卉页
- `月相变化观察` 应链接到月相对象说明页
- `今日云层观察` 应链接到云层类型说明页

### D. 观察方法卡

这些条目移出项目层后，需要补方法脚手架，不然用户会失去“怎么开始”的入口。

建议新增的方法卡包括：

- 怎样填写一次观察记录
- 怎样描述动物行为
- 怎样拍一张可识别的物种照片
- 怎样选择不打扰生物的观察距离
- 怎样记录时间、天气和地点
- 怎样做一次简单的多样性统计

## 四、观察域和挑战层的边界

迁移时最容易再混乱的一点，是把“观察挑战”和“普通观察主题”重新混在一起。

判断规则应固定如下：

- 如果重点是 `今天去看什么`，放观察主题
- 如果重点是 `接下来几天怎么持续做`，放观察挑战
- 如果重点是 `这是什么对象`，放物种 / 对象页
- 如果重点是 `我怎么学会记录`，放观察方法卡

## 五、这 23 项迁移后的直接收益

完成迁移后，会立即解决几个结构问题：

- 项目库不再混入长期观察条目
- 观察内容不再伪装成技能项目
- 观察域内部可以形成稳定的 `主题 -> 记录 -> 物种 -> 挑战` 链路
- 后续地图、搜索、图鉴、连续打卡都会更顺
