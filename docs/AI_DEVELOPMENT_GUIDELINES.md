# AI 开发规范

## 最高优先级规则

AI 功能不得用固定关键词、关键词白名单、正则表达式或字符串包含关系判断用户意图，再决定是否调用模型、检索资源、触发页面工具、诊断图片或附加多媒体。自然语言表达、代词、上下文和多轮对话必须交给大模型判断。

模型应返回短小、结构化的 JSON 决策；服务端随后只负责校验 JSON、能力白名单、候选 ID/slug、数量和范围。模型不可用或输出无法解析时，按功能选择安全的保守降级，不能用另一套关键词规则“补判”。

## 当前实现

| 能力 | 模型负责的判断 | 服务端保留的确定性边界 |
| --- | --- | --- |
| Tutor 站内资源检索 | `resource-search-planner.ts` 判断是否检索、资源类型和主题短语 | `resource-search.ts` 只对模型给出的短语做限量元数据查询；检索未命中不能推断资源不存在 |
| Tutor 页面工具 | `tool-call-planner.ts` 判断是否触发课程、PBL 或扫雷工具 | `tool-registry.ts` 校验当前场景 capability、工具名、payload、步骤和候选积木范围 |
| Scratch 截图诊断 | `scratch-screenshot-diagnosis.ts` 的视觉模型判断是否需要高亮以及候选索引 | 只允许当前步骤的候选积木，低置信度、模糊图或非 Scratch 一律 `no_action` |
| 鸟鸣播放器 | `audio-tags.ts` 的轻量规划器判断是否附加音频并选择候选 slug | 只允许当前场景/站内查询得到的真实音频 URL；规划失败时不附加音频 |
| 五子棋事实注入 | 只依据路由 surface、课程 tags 和课时 `gameKey` 等结构化场景元数据 | 固定事实本身必须原样注入，不由用户文本关键词猜场景 |

## 允许保留的确定性逻辑

以下逻辑不是用户意图分类，可以继续使用确定性实现：

- 登录、权限、scene capability、工具白名单、JSON/schema、ID、数量、长度和 URL 校验；
- 根据模型已经选出的主题短语查询数据库索引，再做状态、权限和结果数量限制；
- 根据结构化路由或课程元数据注入固定事实；
- 根据已知物种名称/别名查找候选资料或音频。这里的名称匹配只负责缩小候选集合，不得替代“学生是否在询问叫声、是否需要工具”等语义判断；
- `lib/content-filter/` 等本地规则用于发布安全、联系方式和防御性拦截时，不得复用成 Tutor 的意图门控，也不能作为需要语义理解的 AI 审核唯一依据。

## Review checklist

新增或修改 AI 路径时，提交前检查：

1. 是否有 `includes`、`match`、`test`、关键词数组或正则决定“要不要调用模型/工具/检索/媒体”？有则改为模型结构化决策。
2. 模型失败是否不会自动执行页面动作、附加未经选择的资源，或把“没搜到”说成“不存在”？
3. 模型输出是否经过 capability、候选集合、schema、范围和权限校验？
4. 测试是否覆盖自然表达、普通知识问答、模型 `no_action`、模型失败和越界输出？
