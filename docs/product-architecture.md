## 1. 已有模块与数据关系

| 对象 | 当前作用与关系 | 主要实现入口 |
| --- | --- | --- |
| 普通项目 | `projects` 提供可自主选择的活动内容、材料与步骤；用户对同一内容的实际尝试另外保存 | 项目详情与 `lib/project/` |
| 课程与课时 | `courses` 组织 `course_lessons`；课时按 Scratch、积木 3D、游乐场实训等类型选择工作区。课程/课时与普通项目各有内容路径，当前不能概括成“一课时就是一个普通项目” | `lib/courses/types.ts`、`lesson-types.ts`、`building-lesson-flow.ts` |
| PBL 挑战 | `challenges` 提供命题与阶段；个人项目方向、阶段产出和最终作品围绕同一次尝试组织 | `lib/pbl/`、`challenge_workspaces`、`challenge_stage_progress` |
| 一次尝试 | 普通项目与 PBL 共用 `project_journeys`，用 `attempt_no` 区分尝试；同一用户、同一来源只允许一个 active Journey | `lib/journeys/types.ts`、`service.ts` |
| 尝试中的记录 | `project_journey_records` 保存阶段、过程与最终作品记录，审核结果回写 Journey；旧项目/PBL 表保留兼容投影 | `lib/journeys/service.ts`、`moderation.ts` |
| 课时进度与作品 | `user_lesson_progress` 保存开始/完成进度；课时作品走独立提交与审核路径，不能用课时完成代替作品发布 | `lib/courses/progress.ts`、`lib/works/submission.ts` |
| 收藏 | `collections` 独立表达以后想看或想做；收藏不创建完成状态，也不替代一次实践 | `/api/projects/[id]/collection` |
| 物理实验室记录 | 主站账号的私密实验存档使用 `physics_lab_states`，与公开项目探索记录分离；复用现有登录、等级及徽章展示，项目详情实验链接留作后续内容关联 | `app/playground/physics-lab/`、`app/api/physics-lab/state/`、[实验室契约](physics-lab.md) |
| 自然观察与统一作品视图 | `observation_events` 保留自然观察领域数据；`lib/works/` 将项目、课时、挑战、自然观察四类成果汇入“我的作品”，汇总展示不意味着底层数据结构相同 | `lib/api/nature-observation-*`、`lib/works/types.ts`、`data.ts` |

### 当前覆盖范围

- Journey 的来源类型是 `project` 与 `challenge`，不包含 `course_lesson`。普通项目可以在一次完成后重新开始新的尝试。
- 课时作品按用户与课时限制为一件 final 作品；审核拒绝后的修改重提不等于保留了多次独立实践。若要支持同一课时多次搭建、比较多个结果，应先确认实际使用需求。
- 课时进度、作品审核、Journey 完成和课程里程碑是不同状态。课时完成写进度；作品经过审核；课程里程碑和奖励按各自受控规则生成。不得把“打开课时”“完成课时”“公开作品”混成一个完成事件。
- 当前记录和进度按用户账号归属。家长账号与孩子学习档案是否需要进一步分开，见下文待讨论项。

课程完成、可信来源、里程碑与奖励详见 [`COURSE_PROGRESS_REWARDS_AND_STEAM_IMPLEMENTATION.md`](./COURSE_PROGRESS_REWARDS_AND_STEAM_IMPLEMENTATION.md)；这些统计口径本身不证明用户的实际问题解决能力。

## 2. 记录与公开发布的当前契约

普通项目的完成记录接口与通用 Journey 项目记录入口，均要求用户明确提交公开审核，不提供新记录的私密保存模式。探索记录至少有文字或图片之一，最终作品仍要求图片；待审不等于已公开。

未发布文字仅在当前标签页按账号和项目恢复。退出、换账号或发布成功后清理；照片、视频不承诺持久化恢复。撤回分享后记录处于未公开状态，重新发布仍须审核。

PBL 阶段保留草稿与可见性操作，底层 `private` / `draft` 字段也服务于撤回状态。不能因为字段存在，或 PBL 可保存阶段草稿，就写成普通项目当前默认私密保存。个人时间线与公开列表也要分别遵守自己的读取契约。

当前准则与验证边界以 [`EXPLORATION_RECORDS.md`](./EXPLORATION_RECORDS.md) 为准；对应实现包括 `lib/project/record-input.ts`、`record-draft.ts` 和 `app/api/journeys/[id]/records/route.ts`。恢复普通项目私密保存属于待讨论的行为变更，本轮仅修正文档。

### 个人中心与探索建议

`/profile` 优先承接继续实践与回看作品，成长数据为次级信息。“继续探索”按当前记录动态推荐，并非用户承诺的固定周计划；领取奖励与更多建议保留，但不以动态队列分母表示计划完成率。探索足迹只反映平台参与记录，不作为能力测评。自然观察进度按已有记录展示。

个人中心摘要失败显示明确错误和重试入口，不渲染为零成果。探索轨迹、成长任务、观察、打卡及进行中项目的请求独立容错，成功摘要继续可用；失败区域明确标识并可重试，打卡失败显示错误状态。已有缓存的刷新失败保留旧数据，并提示未更新。

## 3. 材料、商品与供应商已经分层

| 层次 | 当前实现 | 使用边界 |
| --- | --- | --- |
| 活动所需材料 | 普通项目材料与课程模型零件清单；积木课从 MPD 计算全课/分步 BOM | 描述活动需要什么，独立于是否有商品可买 |
| 用户已有套装核算 | 课程套装配置、零件映射、替代规则和按套数准备表 | 依赖已登记库存与核算规则；无必需缺件不保证实际连接、支撑和替代件都已验证 |
| 可售商品与规格 | `store_products`、`store_product_variants`，通过 `context_keys` 关联课程、课时或项目 | 关联用于呈现购买入口，不自动证明一个 SKU 或多个 SKU 的组合完整满足 BOM |
| 供货来源 | `store_suppliers`、`store_product_sources` 保存供应商与规格来源映射 | 供应商/API 配置存在不代表已取得自动采购资格或完成真实履约 |

课程材料实现从 `lib/courses/lesson-materials.ts`、`course-kit-config.ts` 和 `components/features/courses/lesson-materials-preparation.tsx` 进入。覆盖报告见 [`小班套装对比`](./courses/lesson-kit-coverage-small-class.md) 与 [`中班/大班套装对比`](./courses/lesson-kit-coverage-middle-senior.md)。材料清单核算、模型确认、实物搭建和外部家庭使用分别记录证据，详见 [`content-quality.md`](./content-quality.md)。

后续整理首批体验课程时，应把实际用到的套装、散件、替换和已验证步骤列清楚。商城准备可据此核对真实购买组合，不能直接把课程关联当作材料齐套承诺。

### 探索页「日常材料」

探索页按职责分为学科分类、快捷主题、排序和更多筛选。快捷主题只展示「日常材料」，另提供独立的「按套装找」入口，主题与分类在搜索及筛选结果中继续可见。主题切换只增删对应标签，可叠加（AND），不清除其他主题、难度、年龄、搜索或排序；排序独立选择「热门推荐 / 最新发布」。日常材料沿用材料数量及匹配排序，隐藏排序入口及其说明文字，保留进入前的普通排序值，退出材料主题后恢复。`/explore?tags=日常材料` 和 `/api/projects?tags=日常材料` 共用 `getProjects` 的真实项目查询；该入口不再依赖 Playwright smoke 模式。

桌面不设热门标签侧栏，筛选面板也不再提供标签选择器，项目网格使用完整内容宽度决定列数。探索页 tags 参数只接受「日常材料」主题；其他标签不再用于服务端查询、客户端筛选、条件摘要或生成的分页与规范链接。无有效主题时按未选主题处理。底层项目标签及通用项目 API 的标签能力保持原有职责。手机与桌面按同一列表顺序展示项目，不额外按学科分段；分类由顶部入口切换。普通探索卡片在两端保留年龄与成人陪同提示，完整材料要求与安全说明在具体项目详情中展示。

手机搜索栏常驻「筛选」入口，计数仅包含子分类、难度和年龄，浏览与结果状态共用该入口。主分类只从顶部选择，面板仅提供当前学科的子分类、难度和「孩子年龄」；年龄只影响排序，不排除其他项目。面板重置仅清空这三项，不清除主分类、主题或排序；确认后应用，取消不应用草稿。移动端筛选面板从实际点击的右上角入口展开，落在下方留有边距的浮层；展开约 220ms，内容在 30ms 后开始淡入；打开面板时复用未变化的项目卡片，避免背景列表重复渲染。底部固定重置和查看结果操作，长内容仅在面板内部滚动。关闭时收回入口，保留焦点恢复；减少动态效果模式下不做位移缩放。桌面继续使用右侧抽屉。

筛选后的顶部不再单列「返回探索」；已选条件与弱化的项目数量同行显示，年龄条件写作「优先 N 岁」。两端均不重复显示已在分类、主题入口表达的条件；没有额外条件时不单独显示数量行。筛选入口使用次级文字色与浅蓝计数，材料选择区保持原有功能与顺序。排序入口显示「推荐／最新」，展开时使用统一选择菜单展示完整选项；菜单右对齐，选项保持单行和 44px 点击高度。

探索卡片不显示零点赞、零作品，两项都为零时不渲染统计底栏和分隔线；非零统计保持底部对齐。同一行因标题、材料摘要或统计内容差异产生的自然留白保留，不用零计数填充。手机使用连续双列，不插入学科标题和分隔线。

- 「日常材料」是按内容核对的虚拟分组，不批量改写 `projects.tags`，也不表示某位用户的材料已经齐全。`lib/explore/household-projects.data.json` 维护逐项核对的 447 个真实项目及材料条件（原 311 项，加本轮补齐的 136 项），包含科学、工程、艺术、数学和技术内容；后续扩大集合时须复核该项目的完整材料、具体步骤和来源规格。观察型、仅准备型、依赖未提供说明书或含未识别必需材料的内容不纳入。
- 查询只读取该候选集合，使用与普通列表相同的请求客户端、公开状态、审核状态和分级可见性规则。保留分类、子分类、难度、搜索及其他标签条件；「日常材料」本身不作为数据库标签过滤。候选每批最多 50 项、最多 4 批并发读取，任一批失败不返回不完整结果；完整集合经资格校验后在第一页一次返回，后续页为空，不将普通列表的前 12 项当作整个材料集合。数量以实际公开且通过筛选的项目为准。
- 列表先复用详情的内容覆盖及 `lib/project/content-revisions.ts` 的同源修订，再通过 `lib/project/materials.ts` 解析有效材料。`lib/project/household-profile.ts` 校验项目 ID、标题、分类与有效正文 SHA-256（描述、完整材料、步骤以及科学修订的模式、缺项、安全和来源约束）；内容变化后旧材料条件失效，需重新核对。科学修订内容须匹配真实项目 ID、标题和科学分类；不拿 smoke 的 102/103 样例充当正式内容。保留真实封面、点赞和公开作品数量，客户端只接收卡片所需内容，不携带完整步骤。
- 选中该标签及其进一步筛选结果时，`components/explore/household-material-picker.tsx` 展示「我家有什么」：默认展示纸巾、气球、吸管、水、纸杯五个常见材料快捷项，手机按内容宽度紧凑单行排列，无横向滚动或截断；其他材料由标题旁的「更多材料」文字入口搜索、多选。快捷项以外的已选材料在下方显示可取消标签，与快捷行留出间距。弹层默认展示常用材料，其余按生活场景折叠分类，展开后才渲染该分类选项；搜索覆盖全部类别及原规格别名。主列表只展示常见材料类别名称，原规格名和说明参与搜索；选择器只收集已有材料种类，不枚举具体规格或附带长说明；具体规格、数量及安全要求在项目清单中核对，不能在选择类别后直接推定符合实验要求；材料标签可见高度为 32px，通过透明命中区域保持 44px 点击高度，不拉伸底色填满整行。支持逐项取消与清空，不重复添加操作提示，未选择时卡片仅显示材料数量。选择后顶部展示已选种类及“已按已有材料排序”，有确认匹配的项目时才显示匹配数量。选择保存在当前浏览器标签页的 `steamx:owned-materials:v1` sessionStorage，进入详情再返回或刷新后恢复；存储不可用时仍可当次选择，不要求登录。
- `lib/explore/household-materials.data.json` 保留原材料身份与 `canonicalId`，用于精确项目条件和旧选择兼容；`lib/explore/material-taxonomy.data.json` 是通用名称、必要规格、生活分类、常用项及旧分类迁移的唯一词表。每个目录身份必须有明确词条，不按关键词推断新增材料分类。菜刀、擀面杖、饼干模具、砧板归入「厨房与食品」。地图、图鉴、对照卡及各类参考图按具体名称独立展示，不合并为「参考资料」「参考图片」；选择一种不能代替其他参考内容，具体版本仍需按项目核对。`material-taxonomy.ts` 的 `resolveMaterialTerm` 同时供项目清单与选择器使用；旧同义名称继承目标规格，颜色等额外属性继续保留，已规范名称再次处理保持不变。`material-groups.ts` 按词表生成简洁大类，完整原名和说明参与搜索；具体规格、数量和安全要求在项目清单核对。浏览器保留类别和此前精确选择，旧分类键与原材料 ID 都能恢复，数量按类别去重。类别选择只表示拥有这类材料，只有明确通用要求或已保存的精确规格才能确认匹配；同类而规格未确认的条件单独列为待核对。水溶性、食用、耐热、冷风、瓶口大小等要求继续独立校验，不能据同类推断可替代。瓶装清水属于瓶子的装水规格，不与水视为同义。完整项目条件和正文哈希只在服务端读取。`lib/explore/material-matching.ts` 按明确核对的必需组匹配：组之间全部需要，组内选一项即可；优先选择缺少种类最少、总种类最少的可用组合，共用材料只计一次。卡片携带紧凑的 `householdRequirements`，未知或空条件不作齐全判断，旧样例仍保留已核对源字符串映射。按必需种类去重计数，建议使用的打气筒不参与缺件判断。绳子两端如何系牢属于场地准备，不作为“固定点”材料按钮或缺件计数；正式详情将其从材料条目移至“准备要求”，用椅背等具体例子解释。保留水溶性彩笔、直吸管、透明塑料瓶等规格，棉线与普通细绳分开，不按关键词推断替代品；空清单或未识别的材料不能判定为齐全。
- 未选择材料时按必需种类数升序，卡片材料摘要显示“需要 N 样材料”；选择后按缺少种类数升序，同分时优先待核对规格更少、已有种类更多、所需种类更少的项目，原有顺序作为最后的稳定排序依据。排序覆盖完整合格集合，不因没有全部匹配的项目清空列表。
- 材料卡片与普通探索列表共用网格和图片比例，各行按内容独立定高，同一行保持等高。两种卡片共用图片、标题、正文分类、年龄及成人陪同提示的结构；材料卡片在适龄信息后增加材料摘要，不在封面叠加分类。标题最多显示两行，各信息按内容自然占高，点赞与作品保持底部对齐；普通卡片不为材料摘要预留空白。材料卡片显示“需要 N 样，你有 M 样”，缺一两样时列名称，更多时仅显示数量，同类材料已拥有但规格尚未确认时显示“已有材料，需核对规格”；缺项与待核对规格均为空才显示“材料已匹配”，并计入顶部匹配项目数。完整清单、数量及使用要求仍在详情页；匹配不承诺数量或操作条件已满足。
- Playwright smoke 保留独立样例和占位服务配置，用于离线交互回归；正式数据路径另以非 smoke 查询与浏览器检查验收。样例检查不作为生产内容收录或实物验收的证据。

### 套装与项目配套目录

`/kits` 保留套装选择入口；`/kits/[slug]` 不再渲染中转详情，只根据当前已核对的 SKU 映射跳转商品并选中规格。无有效在售映射或商城关闭时返回 404，不跳到其他规格。目录区分通用材料包和科学实验套装。探索分类描述学习内容，不再按供应商素材来源分组；同一项目可以关联多个套装，也可自行准备材料。目录保存明确版本与包装，本站收录数分别表达已确认配套及同系列待核对项目，不沿用包装标称实验数量作为教程覆盖数。

目录关系与材料准备状态分别核对。原实验目录、材料清单及视频来源用于匹配，名称相同不能自动确认。关系核对绑定实际生效的项目材料、步骤、准备说明、视频依据及套装版本；相关内容更新后重新核对。待核对项目可浏览，数据库确认状态不因展示商品入口自动升级。商城下架不删除套装教程；公开项目仍遵守原审核与访问规则。

套装选择无需登录，在公开商品详情中只在本机记住最近查看的准确规格，不保存账号套装资产或耗材余量。商品和具体 SKU 的规则见商城专题。

### 套装数据与后台维护

开发环境尚未应用套装迁移、数据库返回 `PGRST205` 时，`/kits` 从当前导入清单读取公开字段作为本地预览，并显示预览提示；不模拟项目关联或开放购买。此回退只在 `NODE_ENV=development` 启用，生产不以本地清单替代数据库；其他数据库错误不降级掩盖。

`/kits` 读取独立的 `experiment_kits` 公开目录；旧详情地址仅用于商品跳转，公开项目与教程 API 仍独立保留。`experiment_kit_projects` 维护目录配套关系（候选、确认、不适配），材料准备另记待核对、单次材料已配齐或需要自备；`store_variant_kits` 将站内 SKU 绑定到已核对的套装版本。三表仅服务端可读写，公开服务使用字段白名单，不输出来源证据和采购资料。

管理员通过 `/admin/kits` 与 `/api/admin/kits` 维护清单、目录、项目关系及 SKU 映射；保存请求复用管理员鉴权和同源校验。套装编辑按 edit_version 校验并发，每次修改递增编辑版本；仅影响材料、目录、身份、素材或证据的修改递增内容 revision，单纯发布状态切换不使核对结果失效。项目和 SKU 核对提交必须带管理员实际看到的 expectedRevision；确认项目关系前先载入材料、步骤、准备说明与视频快照，提交 reviewedProjectHash，内容变化时返回 409 要求重新核对。过期的项目审核和 SKU 映射停止作为已确认配套使用。项目核对指纹覆盖生效正文、材料呈现、准备说明与视频依据；直接编辑准备说明也会使旧核对失效。

项目详情展示已确认的配套关系及当前版本的科学实验套装目录关系，后者按负责人确认展示对应 SKU 入口，数据库核对状态保持独立。通用材料包仍仅在已确认、准备要求明确时提供购买推荐。所有项目入口均按当前版本的科学实验套装目录关系加载已核对的在售 SKU，不依赖 `?kit=slug`。材料包占位条目直接链接到唯一对应规格；多个对应规格逐项列出，不任意挑选。此导航不提升候选核对状态，无映射时不猜测商品。科学套装及 `metadata.kitManaged=true` 商品不会通过旧 `context_keys` 回退推荐全部规格。通用材料包推荐仍要求已核对、自备项明确且有当前 SKU 映射；所有链接均校验商城状态、商品状态及规格状态。

商品详情通过教程 API 加载列表并原地加载更多，不再链接回旧套装详情。API 分页先展示已确认关系，再展示候选；项目读取沿用公开审核和分级可见性。页面计数标注为本页收录数，供应商实验数量不作为本站教程覆盖数。耗材、自备条件及内容验证标准见 [内容质量](content-quality.md)，售价、运费与履约规则见 [商城决策](STORE_CHANNEL_FULFILLMENT_DECISION.md)。

## 4. 网站学习与商城准备的边界

`lib/store/service.ts` 的上下文商品查询在目录关闭或商品查询失败时隐藏购买卡片，继续提供学习内容。目录、新购、真实支付及具体支付渠道分别由配置开关控制；关闭新购不等于停止处理历史订单和售后。

因此，本次确定的“推广可用网站内容，同时推进商城准备”已有实现基础。已有匹配材料的家庭可以参与内容体验；缺材料的家庭需要看到准确的材料要求和当前购买状态。支付审核、供应商接入与自动采购条件不应阻断已有免费学习路径。

当前首期交易和履约方案、默认关闭的开关、真实交易验收要求以 [`STORE_CHANNEL_FULFILLMENT_DECISION.md`](./STORE_CHANNEL_FULFILLMENT_DECISION.md) 为准。本文不改变现有人工采购/供应商代发方案，不承诺已经开售或支持 1688 自动下单。

## 5. 待讨论，尚未采纳为开发需求

| 问题 | 已有基础或限制 | 决定前要弄清的使用场景 |
| --- | --- | --- |
| 家长账号与孩子档案分开 | 现有进度、Journey 和作品按账号归属 | 一个家庭是否确实需要为多个孩子分别续学、记录与展示成果 |

| 普通项目私密实践记录 | 当前普通项目只接受公开审核提交；PBL 可保留阶段草稿 | 是否有人需要长期保存但不公开；若采纳，需明确保存、发布和撤回的产品含义 |
| 实践绑定学习内容版本 | LDraw 确认已绑定模型哈希，课程里程碑已有部分配置快照 | 哪些内容更新会影响继续学习或复现；不能把局部快照称为全部内容版本已绑定 |
| 项目与课时复用内容 | 课程/课时、普通项目各有内容结构 | 哪些实际内容重复维护，复用会如何影响发布、修改和历史记录 |
| 观察、实验工具关联项目实践 | 自然观察和游乐场有各自记录/状态，现有 Journey 来源限于项目和挑战 | 是否有跨模块实践需要引用观察或实验结果；先保留时间、地点、物种或实验配置等各自语义 |
| 模块是否独立部署 | 学习与商城已存在代码及配置边界 | 结合真实故障、变更频率、运行负载和维护成本决定，不能仅凭模块数量要求拆服务 |
