# 产品设计全面评审（2026-08-14）

> 数据来源：线上库 `spb-bp1n04y14st4y299`，2026-08-14 实测。代码依据均标注文件路径与行号。
> 本轮范围：P0 与 P1 已落地。P2 里本轮只做三块：会员字段保护、已过审观察记进雷达 S、讨论区残留清理；其余继续冻结或盯数据。

## 一、核心结论

**供给过厚，需求未验证。**

平台已经建成了一个功能面极宽的产品：242 个已上架项目、316 节课、18 款游乐场小游戏、576 种物种档案、AI 导师、游戏化体系、社交与审核体系。但需求侧接近于零——**46 个真实账号里，只有 4 个人产出过作品，一共 12 件**。

因此本次评审的第一结论不是某个界面要改，而是：**停止加宽功能面，选定一条「第一次成功」路径并只优化它**。

该路径已定为**积木课**：挑一节积木课 → 跟 3D 分步搭出来 → 拍照上传 → 拿到反馈。

**唯一北极星指标**：注册后 7 天内产出第一件作品的人数（现状 4 人）。

## 三、六个结构性问题

### 1. 供给过厚、需求未验证

供给与需求相差三个数量级。242 个项目里 240 个从来没有人做过；300 节积木课只有 2 个人开始学；18 款游戏、576 种物种档案是完整建成的功能面，但都不产生作品。

这不是「内容还不够多」的问题，是**内容与用户之间没有一条被验证过的通路**。继续加宽功能面只会稀释本就稀薄的注意力。

### 2. 没有唯一的「第一次成功」路径，概念与入口过载

一个新用户在做任何事之前，产品给了他至少**七个平级的「从这里开始」**，指向五个不同频道，且互相不一致：

| 位置 | 指向 |
|---|---|
| 首页 hero 两个按钮（`components/home/home-showcase.tsx:139-159`） | `/explore`（主）、`/create`（次） |
| 首页「从这里开始」六块磁贴 | `/explore?category=X`、`/playground` |
| 顶部导航（`components/layout/main-nav.tsx`） | 探索 / 创造营 / 排行榜 / 自然观察 / 游乐场 |
| 底部导航（`components/layout/bottom-nav.tsx`） | 首页 / 探索 / 创造营 / 自然 / 我的 |
| `ProfileStarterHub`（`app/profile/page.tsx:513`） | 发布第一个项目 / 记录第一只鸟 / 去参加社区挑战 |
| 起步周计划（`lib/profile/weekly-plan.ts:295-336`） | 发布第一个项目 / 记录第一条自然观察 / 逛逛游乐场 |
| 新手引导第一条（`lib/profile/growth-tasks.ts`） | 写一句自我介绍 |

更糟的是，**当前主 CTA 指向的 `/explore` 恰恰是最难成功的一条路**：242 个教程模板中 240 个零作品，没有同龄范例可模仿，孩子要自己备料、自行判断做完没有、还要分清「探索记录」与「终稿」两个概念。

五条产出路径横向对比「新手能否一次成功」：

| 路径 | 能否保证成功 | 现状 |
|---|---|---|
| 探索项目 | 难 | 需自备材料、自组织步骤，240/242 无范例 |
| **积木课时** | **几乎必然** | 300 节免费、免登录可看、3D 分步 + 成品图对照 |
| PBL 挑战 | 很难 | 仅 1 个挑战、多阶段、0 份投稿 |
| 自然观察 | 不可控 | 依赖出门 + 找到生物 + 天气季节 |
| 游乐场 | 必然成功 | 但不产出任何作品 |

**移动端更严重**：`home-showcase.tsx:139` 的按钮容器是 `hidden ... md:flex`，手机首屏只有标题「探索 · 创造 · 成长」、一句副标题和四个小标签，**一个按钮都没有**。第一个可点元素是往下滚之后的自然频道「立即进入」和排行榜「查看榜单」。

**词汇同样过载**：项目 / 作品 / 终稿 / 投稿 / 探索记录 / 观察记录，六个词描述同一类事物。五条产出路径中只有两条汇入 `/works`，PBL 投稿与自然观察各自独立，用户没有一个统一的「我的成果」视图。

**待办面板同样过载**：个人主页桌面端同屏挂着三个待办面板（`app/profile/page.tsx:459` `PrimaryPlanCard`、`:513` `ProfileStarterHub`、`:537` `GrowthTasksPanel`），加上周计划失败时的「今日行动」降级卡共四套，说的是同三件事；移动端反过来只有周计划，5 项引导清单不渲染。而 `lib/profile/weekly-plan.ts:178-191`、`:266-279` 说明周计划本来就已经把引导任务当输入消费，是它的超集。

### 3. 社区互动信号主要来自机器人

15 个自动互动账号（`supabase/migrations/20260605100000_auto_interactions.sql:28-73`）在内容审核通过后延迟 2–90 分钟自动点赞、收藏、并生成拟人化短评。这些账号有真实感的用户名、头像和个人简介（「喜欢做小实验，也会记录路边看到的植物。」），默认开启（`lib/auto-interactions.ts:64`），界面与 `app/legal/terms` 均无任何披露。

生成短评的 prompt 明确要求**不得提及 AI**（`lib/ai/auto-reply.ts:101-107`）。

实测占比：全站点赞的 96%、项目评论的 63%。也就是说，一个孩子上传作品后收到的绝大多数「反馈」，来自程序。

对儿童平台而言，拟人化短评是这里最尖锐的部分——它会让孩子相信有真人在跟自己说话。

### 4. 陌生人可无门槛私信儿童

`profiles.message_privacy` 的数据库默认值是 `everyone`（`supabase/migrations/20260318200000_p0_safety_reports_privacy_age.sql:74-77`），任何登录用户都可以私信任何孩子。

而「仅关注我的人」这一档形同虚设：关注是单向一键的（`hooks/use-follow.ts:55-74`），陌生人点一下关注就能通过 `app/api/messages/send/route.ts:76-87` 的检查。

当前的额度限制（`send/route.ts:53-57`）对所有关系一刀切地给 3 条，不区分陌生人与熟人；首条消息的外链/邮箱/手机号限制只在 `!hasReply` 时触发（`send/route.ts:58`），实际只覆盖第一条。

### 5. 奖励承诺与实际发放不符

- `components/features/gamification/level-guide-dialog.tsx:85-134` 宣传的 Lv2「评论区发图特权」、Lv20 帖子曝光、Lv30「商店全场 8 折」、Lv50「社区核心自治提案参与权」——**四条全部未实现**，或随讨论区下线而失效。
- `lib/gamification/experience-rules.ts:33-36` 仍在宣传「评论」「发起讨论」可得 XP，但这两项**已停止发放**。
- `complete-project-dialog.tsx:511-513` 在「过程记录」模式下也显示「可获得 20 XP」，但过程记录实际发放 **0 XP**。

对一个以成长激励为核心机制的儿童产品，兑现不了的承诺比没有承诺更伤。

### 6. 家长价值完全缺位

家长是决策者和付费方，但产品目前没有给家长任何东西：

- **没有结课凭证**：学完 100 节课只有一句 toast（`lib/courses/progress.ts:93-97`），没有可保存、可转发的成果物。
- **没有零件清单**：`lib/utils/ldraw-bom.ts` 的 BOM 能力已就绪，但没有任何界面暴露。家长不知道该买什么积木。
- **搜不到、转不出去**：`app/sitemap.ts` 完全没有课程 / 课时 URL，300 节免费课在搜索引擎上不可见；`share-work-dialog.tsx` 的 `ShareCardContent.kind` 只有 `work` / `project`，课程无法生成分享卡。
- **教师/家长引导是死代码**：`content.teacherGuide` / `learningGoals` 的 UI 已完整实现（`lesson-sidebar.tsx:154-218`），但线上 316 节课**两个字段均为 0 条**。

关于最后一条，值得记录来龙去脉：这个字段**不是没人填过**。`20260627172000`、`20260627174000`、`20260628125000` 三个迁移曾为两门手写试点课（「小小积木工程师：学前大颗粒启蒙」「大颗粒积木工程启蒙」）写满了 24 节课的探究问题、材料准备、引导提问、观察记录、延伸与带回家话术。但 `20260628220000_remove_legacy_brick_courses.sql` 把这两门课整门删除、换成现在的 3+/4+/5+ 课件100 之后，字段就一直空着。**那 24 节的引导文案是目前站上唯一成型的家长话术素材，保留在 git 历史中，将来做家长引导可直接取用。**

## 四、已定决策

| 决策 | 结论 |
|---|---|
| 主线路径 | **积木课**：挑课 → 3D 分步搭建 → 拍照上传 → 拿反馈 |
| 北极星指标 | 注册后 7 天内产出第一件作品的人数（现状 4 人） |
| 自动互动账号 | 保留自动点赞与收藏；**删除拟人化短评**；不加机器人标识 |
| 私信 | 保留功能，加递进门槛：陌生人 1 条 → 互关 3 条 → 对方已回复后正常聊 |
| 新手引导 | 并入本周探索计划，个人主页只保留一个待办概念 |
| 作品词汇 | 收敛为三词：**课程/项目**（跟着做的）、**作品**（做出来的）、**记录**（过程） |
| 五条产出路径 | 全部汇入 `/works`，包括 PBL 投稿与自然观察 |
| `teacherGuide` / `learningGoals` | 删除全链路（死代码），迁移文件保留 |

### 关于自动互动账号的遗留风险

本次决定保留自动点赞与收藏、且不加标识。需如实记录：**冷启动期的点赞数仍将以机器人为主（当前 96%）**，这会影响排行榜与「受欢迎」类排序的真实性。等真实用户量上来后应复评是否关停。

删除拟人化短评消除了最尖锐的部分——孩子不会再误以为有真人在跟自己对话。

### 复审修正（同日）

四批改完后逐条复查，发现并修掉四处：

1. **注册落地主线是死代码**。落地页判断挂在 `emailMode === 'sign_up'` 上，但真实注册走的是默认那个手机号验证码表单，`emailMode` 始终是 `sign_in`（切到 `sign_up` 的唯一入口会同时切成邮箱，而邮箱注册是被拒的）。改成由 `sms/verify` 回传 `isNewUser`——它本来就是在 `phone_to_user` 查不到映射时建号的那一方，魔法链接的 `redirect_to` 也一起跟上。
2. **结课凭证的作品册会点出 404**。RLS 允许本人读到自己未过审的作品，而 `/works/[id]` 只放行已过审且公开的，作品册照原样渲染就会点出 404。现在按同一口径过滤，未过审的只报「N 件审核中」。
3. **`followers_only` 语义前后不一致，且掐断了已有会话**。接口只要求「对方关注了我」，按钮却要求互关；同时这一档在关系判断之前就拦，接收方切档位会让已经在聊的人发不出消息。统一成「真互关，或对方已经回复过」，回复本身就是最强的同意信号。
4. **零件清单页把临时失败当 404**。BOM 并发超限或读文件失败原本和「没配模型」一样返 404，而这些 URL 在 sitemap 里。现在区分三态，临时失败渲染「清单正在生成」。

同时把私信历史判定从「取会话最早 20 条再推断」换成「对方发过消息没有」的存在性查询 + 自己发出条数的 count，历史长会话不会再被误判成陌生人。观察记录的点赞/评论数经核对读的是 `observation_events.likes_count` / `comments_count`，没有问题；挑战作品显示 0 也符合事实——它本来就没有点赞和评论表。

## 八、落地后要盯的事

P0 与 P1 已全部落地（2026-08-14）。P2 里会员字段保护、观察记进雷达 S、讨论区残留已做；游乐场、全天候观察、金币/会员产品、私信请求样式仍冻结。接下来该看的是数据，不是再加功能：

- **唯一北极星**：注册后 7 天内产出第一件作品的人数。改版前是 4 人 / 12 件。这个数字不动，说明主线收口没解决问题，那就该回头质疑「积木课是不是真的是最容易成功的那条路」，而不是继续往上加入口。
- **主线漏斗要能分段看**：进 `/courses` → 打开某节课 → 完成课时 → 上传作品，四步各自的流失率。哪一步掉得最狠，下一轮就只修那一步。
- **私信门槛的副作用**：陌生人首条被拦掉多少、其中多少后来变成互相关注。如果拦截率很高但互关转化接近 0，说明门槛挡住的是正常搭话而不是骚扰，额度常量（`STRANGER_MESSAGE_LIMIT` / `MUTUAL_FOLLOW_MESSAGE_LIMIT`）就该调。
- **机器人点赞占比**：删掉拟人化短评后，真人互动占比有没有回升。这个数字长期停在个位数，就说明社区还是空的，弱信号点赞只是在掩盖它。
- **结课凭证的实际触达**：目前只有 8 节的 Scratch 课和五子棋课现实中可能学完，100 节的积木课几乎不可能。如果半年内没人拿到凭证，凭证的门槛（整门课完成）就得改成阶段性的。
