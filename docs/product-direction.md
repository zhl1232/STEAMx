# 产品方向与当前约束

> 更新于 2026-10-12，依据本次产品讨论及 `main` 的 `f4eb9e8caee04d79997d9ed4f9401f3f8dcf2510` 文档、关键实现对照。本轮未重新核验生产环境；历史数量、开关和发布记录仍须保留各自日期与证据。

## 长期方向

创探空间是兴趣驱动的 STEAM 项目学习与自然观察平台。希望帮助学习者在真实问题中反复经历「分析问题 → 动手尝试 → 观察反馈 → 调整 → 再尝试」，逐步形成能用于生活、学习和工作的解决问题能力。

积木、科学实验、Scratch、自然观察和探索工具是不同入口。保留按兴趣选择的自由，也可以提供短小的引导路线；课程完成数、奖励或雷达变化不单独证明解决问题能力已经提升。

## 当前阶段与首批用户

截至 2026-10-12，项目负责人确认：尚未推广，尚无外部用户反馈；目前最有把握的体验是浏览和寻找内容。部分小班大颗粒课程已有实物搭建验证，但具体课时、所用套装和散件仍需整理，不能扩展为整门课程全部验证通过。

首批重点验证：**已有匹配积木、愿意陪幼儿园阶段孩子搭建、需要新创意和指导的家长**。这是阶段性用户假设，不永久缩窄平台方向；尚无外部反馈也不能作为没有需求的结论。「匹配」要按实际零件、数量和替代方式确认，拥有任意大颗粒套装不等于材料齐全，部分课程需要多套或散件组合。

## 当前主线

先通过小范围定向体验验证可用课程，网站推广与商城准备并行。当前学习路径是：

`找到感兴趣的课 → 核对材料 → 开始搭建 → 观察与调整 → 完成作品 → 再选择一节课`

保留「注册后 7 天内产出第一件作品的人数」作为核心观测指标，统计时写清注册批次、观察窗口和作品证据来源；如报告比例，注明分母。首轮另记录材料是否匹配、是否实际开搭、卡点、是否完成，以及完成后是否再次选择或开始课程。

上传不是实际完成的唯一证据：家长反馈、现场观察或作品照片可以帮助判断完成，但必须区分证据来源，不能伪造站内完成或公开作品。未上传、正在审核、已完成但未再次使用应分别记录。分享与获取反馈作为后续选择，普通项目记录的提交和审核规则仍按 [探索记录说明](./EXPLORATION_RECORDS.md) 执行，不由本次讨论改成私密保存。

优先保证用户有可完成、可调整的实践，再引导作品分享、评论或奖励。新增功能应说明如何帮助这条路径，或补足哪一项真实观测；首轮可以先用少量体验反馈，不以新建完整统计系统、商城开售或整体重构为推广前提。内容、一次实践和成果的关系见 [产品架构说明](./product-architecture.md)，内容验证口径见 [内容质量规范](./content-quality.md)。

## 新人入口、欢迎与帮助

2026-10-13 确认的移动端原则：方向选择只做一次，详细指南按需阅读，不将任何单一方向设为全站新人的必做任务。

- 注册有明确返回地址或待继续操作时，仍回到原内容；没有目标的新用户进入 `/start`。不改 Auth、登录回调或老用户返回行为。
- `/start` 只并列提供搭积木、做小实验、学编程、去自然里观察四项。分别直达积木分类课程、科学分类项目、编程分类课程、自然首页；保留“先随便看看”和低强调客服入口。不要加入问卷、默认观察任务、重复“下一步”、入群要求或奖励清单。
- `/courses?category=brick|programming` 用服务端校验后的分类初始化课程列表；同一路由换方向时重置列表状态。未知/重复参数回到推荐视图；加载失败重试保留有效分类；空分类显示真实空态，不伪造推荐课程。
- `/learn/*` 保留为可选帮助和既有链接落地。“看看观察方法”仅阅读指南；记录仍由 `/nature/submit` 承接，不创建新的观察流程。具体材料、安全和发布隐私要求不因入口简化而移除。
- 注册欢迎只用短句与一个“选一个开始”主行动；在开始页内不再显示回到自身的主行动。欢迎不是平台公告，普通介绍不升级为弹窗；本次不更改公告等级、投递、安全提醒或后台自定义公告。
- 客服统一使用 `lib/product/support.ts`；`/about#support` 与旧 `/about#contact`、`/settings/about#contact` 均落到客服区。站内反馈优先，微信号按实际配置展示且可复制；没有号码时展示现有客服二维码，不虚构号码。入群说明独立且可选；公众号订阅独立在 `#official-account`。
- 欢迎文案迁移只匹配两版已知默认文案和旧客服地址，保留管理员自定义内容、标题、关闭状态及激活时间，不重发欢迎、不修改已发送历史消息或公告。迁移按 [数据库迁移规范](./database-psql.md) 在获授权的环境和名单内执行；代码补丁不等于线上配置已经更新。

回归入口：`lib/product/onboarding.test.ts`、`lib/product/support.test.ts`、欢迎组件与开始页/课程入口测试、`e2e/mobile-onboarding.spec.ts`；迁移静态检查见 `__tests__/mobile-onboarding-migration.test.ts`，离线执行检查见 `scripts/test-mobile-onboarding-migration.mjs`（显式指定已安装的 PGlite 模块，不连接远端库）。

## 当前有效约束

- 免费课程保持公开可用，课程流程不设置付费墙；会员能力只能补充工具、答疑或 AI 配额，不能阻断首次成功路径。
- 面向儿童的界面不使用倒计时、限时优惠、名额告急等逼单表达，也不在孩子的学习流程中推动购买。
- 主线内容应给出清晰任务、完成标准和可选支撑，同时保留用户设计、测试和迭代的空间；挑战不能退化成固定答案的教程。
- 互动安全资格、会员、角色和成长奖励各自独立。公开阅读与保存进度的门槛不能被会员绕过，互动写入必须服从当前安全规则。
- 自动化互动不得伪装成人与儿童对话。任何冷启动信号都不能被当作真实用户需求或作品质量的替代证据。
- 家长价值应通过可保存的作品、课程完成反馈、材料清单和清晰的学习进展体现；这些能力必须服务于学习闭环，不能抢占孩子的主任务。

## 商城与实物履约边界

支付申请尚未通过，1688 对接自建站存在准入门槛。**可用的网站内容先推广，材料方案、支付准入和供应商履约条件同步准备；1688 自动采购和商城开售都不是内容推广的前提。** 优先让已有匹配材料的家庭体验；缺材料的用户可以浏览内容与要求，购买入口应如实反映尚未开放的状态。

既有首期方案仍是站内交易、人工采购与供应商代发，详见 [商城决策](./STORE_CHANNEL_FULFILLMENT_DECISION.md)。本次没有改变履约范围，也不以当前手动流程推定长期人工运营已被接受；网站推广不要求同时开始人工接单。代码存在不证明支付、采购和发货已经可用，实际开售仍按该文档完成准入、配置和交易履约验收。

免费学习与材料要求独立于商品供应，购买不作为课程完成条件。材料需求、购买方案和供应商分别维护；商城关闭或商品不可用不应阻断已有材料用户的学习。
