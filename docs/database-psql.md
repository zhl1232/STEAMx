# 数据库连接与迁移

核对：2026-10-13，`0d322eda40dfdf81c7feb4f37703c9b38bea2b15` 的 `scripts/db-push.mjs`。本文是数据库连接、迁移命令及副作用的唯一文档来源；[部署说明](deployment.md) 负责应用切换与恢复，不另行定义迁移命令。

## 当前接入方式

项目使用第三方托管的 Supabase 兼容服务。正式迁移由自定义工具通过 pg-meta `/pg/query` API 执行，不是 PostgreSQL 直连，也不使用官方 `supabase db push`。不能假定新建一个官方 Supabase 项目就具备此 API、认证头及权限。

迁移在 `supabase/migrations/`，文件名为 `YYYYMMDDHHMMSS_description.sql`；追踪表为 `public._schema_migrations`。保留完整迁移目录和已执行历史；不要逐个重跑旧 SQL、清空 schema、改写旧 ID/哈希或删减目录来隐藏待执行项。

## 配置与授权

工具读取已有进程环境，并在缺值时读取项目根 `.env.local`：

| 变量 | 用途 |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | 已确认目标实例的服务地址 |
| `SUPABASE_SERVICE_ROLE_KEY` | 仅服务端保存，用于已授权的 pg-meta 操作 |

前端 anon key 不足以执行迁移。密钥不得放入 `NEXT_PUBLIC_*` 自定义变量、仓库、文档、日志或 PR。生产使用服务器已有配置，不能因为本地文件名叫 `.env.production` 就认定它已同步到服务器。

执行前明确目标环境、全部待执行迁移、批准名单和必要备份。只要求生成 SQL 或整理文档，不代表允许运行迁移、baseline 或初始化追踪表。读取远端也需在已确定的诊断范围内进行。

## 命令模式与副作用

| 命令 | 行为 | 是否数据库只读 |
|---|---|---|
| `pnpm db:status` | 查看已执行/待执行，先尝试创建追踪表 | 否 |
| `pnpm db:push -- --dry-run` | 不执行迁移正文，但先尝试创建追踪表 | 否 |
| `pnpm db:push` | 初始化追踪表并应用所有待执行迁移 | 否 |
| `pnpm db:baseline` | 将现有迁移标记为已执行，不代替实际建表或迁移 | 否 |
| `pnpm db:push -- --only=<完整文件名逗号列表> --dry-run` | 限定发布预检，要求已有追踪表；检查完整目录和名单外待执行项 | 是 |
| `pnpm db:push -- --only=<完整文件名逗号列表>` | 通过预检后，在一个事务中提交本次待执行 SQL 与追踪记录 | 否 |

`--only` 只支持 `push`，完整文件名不带路径、不含重复或空项；名单无效、追踪表缺失或存在名单外待执行迁移时停止。批准但已经执行的迁移跳过。限定模式不会自动初始化或 baseline。

“只读”只描述限定预检的 SQL 副作用，不表示免认证、免授权、离线执行或可以输出凭据。其他名称含 `dry-run` 的脚本不得推定具备相同性质。

### 已批准批次的操作顺序

1. 从本次获授权的版本确定完整迁移名单，并与相同版本的 Release 配置核对；不要使用通用文档中写死的“上次三条”。
2. 保留完整目录，先运行限定只读预检；发现其他待执行项或追踪缺失就停止，不以 baseline 绕过。
3. 只有获得该环境和批次写入授权后才运行限定执行；保存提交、环境、结果及应用版本。事务失败则阻止应用切换。
4. 单独验证相关业务；记录写入成功不等于语音、计费、登录或用户余额均已验收。

具体名单快照见 [2026-10-13 发布记录](releases/2026-10-13/runtime-migrations.md)。记录是版本证据，不授予执行权限。

## 新环境与首次接入

新建空库、接入已有业务库、升级现有库必须分开制定方案。空库不能直接 baseline，否则只会产生“已执行”标记而缺少实际结构。已有库接入必须先证明结构、权限和既有迁移状态一致，再在明确授权下处理追踪；当前限定发布流程不是自动初始化工具。

## 需要直连时

直连仅用于已获授权的诊断或单次运维，不替代正式迁移追踪。先在托管控制台核对实例、网络白名单、主机、端口、数据库和账号；不从控制台跳转 URL 猜地址。连接参数以实际实例为准，密码通过安全交互或凭据管理提供：

```sh
psql -h <实际主机> -p <实际端口> -U <实际用户> -d <实际数据库>
```

日常部署不使用 `psql -f` 逐条重跑迁移或 seed，不在命令行示例中写明文密码。人工诊断也不默认允许更改 Auth 用户、手机号映射或业务账本。
