# 探索记录发布流程

探索记录以文字为主，允许只写文字或只添加图片；两者不能同时为空。最终作品仍要求图片。点击“发布记录”才提交审核，恢复本地文字不会自动提交。

项目完成记录接口与通用Journey的项目记录入口均使用公开审核契约，不提供私密保存模式。未提交文字仅在当前标签页按账号、项目恢复；切换账号、退出登录或发布成功清理，发布失败保留。照片、视频文件不持久化恢复。

记录状态依次为明确提交、待审、通过后公开。初次发布和重新发布不会提前填写published_at；公开列表和计数仍要求is_public=true、status=approved、moderation_state=approved。撤回分享退回未公开，重新发布再次审核。

底层private/draft字段保留给撤回状态及PBL阶段草稿，不新增数据库结构、不变更RLS、不批量迁移既有记录。

开始探索防重复点击，失败显示重试提示；记录列表/详情读取错误与空列表分开，失败保留已有内容并允许重试。发布提示按服务端返回状态显示，异常draft响应不能视为发布成功。

隔离验证覆盖文本/图片/空白校验、重复提交、失败恢复、账号切换与退出清理、旧上传结果失效、审核状态、公开计数过滤和撤回再审核。测试使用mock边界，不代表真实数据库、Storage或审核服务的端到端验收。

## 项目问答与作品交流

项目步骤下以“作品 / 讨论”切换，默认展示作品。标签采用下划线选中态，正文输入与图片、发布操作收在同一输入面板中，空态仅提示“还没有讨论”。材料和步骤卡片不再重复放置提问入口；讨论输入区仅保留正文、添加图片和发布，回复时显示可取消的回复对象或上下文。无需先发布作品，无必填标题或分类，不常驻展示奖励、草稿或新旧数据说明。

讨论通过 `/api/projects/[id]/questions?includeLegacy=1` 将新问答与已审核的旧项目留言统一按根留言 ID 倒序分页，展示作者、时间、正文及回复关系，不再设置历史留言入口。旧留言保持原有身份且只读，不转换为新问题、不触发奖励或质量反馈；作品评论仍留在各自作品中。新问答继续通过原接口发布和回复，旧 `/api/comments` 写入口仍退役，原 GET 不带 `includeLegacy=1` 时仍只返回新问答。回复一层缩进显示被回复者，先显示两条、其余展开。

作品详情的留言使用 `/api/completions/[id]/comments?pagination=cursor&limit=10` 按 ID 升序分批读取，每批 10 条合计根留言与回复；`after` 使用上批返回的 `nextCursor`，到末尾为 `null`。已加载页面累积去重，跨页回复归入原线程；每条线程仍先显示两条回复，其余展开，分页状态显示已加载的留言与回复数。首次或追加加载失败提供重试，追加失败保留已有内容；发布和审核轮询会顺序刷新已加载各页；发表成功明确提示已提交、审核通过后公开，不为寻找新留言自动读取全部后续页。已有不带 `pagination=cursor` 的预览调用保持原 `limit` 契约。分页继续使用当前访问资格和数据库 RLS，不额外公开不可见父留言下的孤立回复。

问题文字和上下文仅按账户/项目存当前标签页会话草稿；匿名输入在内存中保留给登录回调，不持久化；切换账户、退出或成功发送清理，照片不存草稿。新问题附图复用上传与服务端图片安全链，图片安全未确定时不公开。列表按20个根问题翻页，当前页最多取200条回复；旧留言沿已公开父回复逐层读取，最多20层，达到上限时明确提示回复未全部展示。超大型单线程完整分页尚待扩展。

已登录问答草稿在作品/问答标签切换或组件重新挂载后，保留原回复对象和材料/步骤上下文。兼容已有草稿中的材料/步骤上下文与程序化上下文事件；显式事件仅消费一次并取消原回复对象，不在后续恢复草稿时重放，页面不再展示重复的快捷提问入口。

AI 发布安全与质量判断分离，标签与实际XP分离；具体额度、撤回恢复、人工兜底和费用边界见[成长奖励契约](COURSE_PROGRESS_REWARDS_AND_STEAM_IMPLEMENTATION.md)。普通感谢可发，具体短问题不因篇幅短被排除；内容依旧接受举报和人工复核。
