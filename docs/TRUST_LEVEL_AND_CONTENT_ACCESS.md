# 内容门禁与互动资格

> 状态：第一版已实现，年龄门禁前端闭环和互动写入收口已补齐。最后更新：2026-08-03。

## 1. 目标

这套规则的第一目标是提高注册转化，而不是把公开内容全部锁住：

- 未登录用户可以继续浏览公开首页、探索、课程简介、项目详情、挑战说明、自然观察和物种图鉴。
- 注册后立即获得保存学习进度、收藏、关注和继续学习的价值。
- 在投稿、评论、发帖、发起私信等会产生公开或对外内容的动作前，再要求一次本人年龄确认。
- 限制状态独立于注册、XP、会员和角色，不能靠刷经验解除。

第一版不按 Trust T0-T4 锁定知识正文，也不把会员权益、XP 等级和社区安全资格混成一套等级。

## 2. 四条独立轴

| 轴 | 用途 | 不承担的职责 |
|---|---|---|
| XP | 成长反馈、徽章、排行榜和经济奖励 | 不决定评论、投稿、发帖或私信权限 |
| Membership | 会员阅读或产品权益 | 不绕过互动安全门禁 |
| Role | 教师、审核员、管理员职责 | 不自动获得普通用户的互动旁路 |
| Interaction access | 判断当前账号能否执行某个动作 | 不展示成用户等级，不替代审核 |

不再实现 T0-T4 五级 Trust。产品界面只展示用户能否完成当前动作，不展示“信任等级”。

## 3. 互动状态

### 匿名

可以阅读公开内容；需要保存进度或产生个人数据时先注册/登录。

### 已注册

注册或登录成功，但尚未完成本人年龄确认。可以：

- 保存课程、项目和 PBL 阶段进度；
- 继续学习、上传草稿、收藏、关注和点赞；
- 对公开项目、作品和自然观察执行点赞、收藏、关注及打赏等 `engage` 操作；
- 浏览公开内容。

暂不能：

- 发布项目、课程作品、挑战作品或自然观察；
- 评论、回复、鉴定和挑战评分；
- 发起帖子或发送私信。

### 已确认可互动

已注册且 `profiles.age_confirmed_at` 有值，可以执行投稿、评论、发帖和私信。所有操作仍受内容安全检查、审核、频率限制和接收方隐私设置约束。

### restricted

独立的 `profiles.interaction_restricted` 状态。开启后禁止保存进度和所有上述互动写入，但保留必要的公开阅读以及管理本人已有内容的能力。该字段不能由普通用户修改，供后台限制流程使用。

## 4. 年龄确认

- 第一版只支持本人确认，不支持监护人代确认或管理员代确认。
- 短信验证码只证明手机号控制权，不自动代表年龄确认。
- 注册页只需要同意《服务条款》和《隐私政策》，不在注册第一步放年龄门槛。
- 用户可在首次需要投稿或互动时前往“设置 → 账号与安全 → 本人年龄确认”，也可以提前完成。
- 确认接口使用服务端 `confirm_my_age()` RPC 写入时间戳，普通客户端不能直接修改 `age_confirmed_at`。
- 历史注册流程曾自动写入该字段；迁移会清空这些旧值，历史用户需要重新完成本人确认。
- `birth_date` 只用于年龄段推荐，不等同于年龄确认。

## 5. 能力矩阵

| 能力 | 匿名 | 已注册 | 已确认 | restricted |
|---|---:|---:|---:|---:|
| 浏览公开内容 | 是 | 是 | 是 | 是 |
| 保存进度/继续学习 | 否 | 是 | 是 | 否 |
| 收藏、关注、点赞 | 否 | 是 | 是 | 否 |
| 作品/自然观察点赞、打赏 | 否 | 是 | 是 | 否 |
| 投稿、上传观察、发布作品 | 否 | 否 | 是 | 否 |
| 评论、回复、鉴定、评分 | 否 | 否 | 是 | 否 |
| 发帖/创建公开项目 | 否 | 否 | 是 | 否 |
| 发起或回复私信 | 否 | 否 | 是 | 否 |

服务端使用 `requireInteractionAccess()` 统一判定，不信任前端按钮状态。当前已接入：

- 项目创建、项目/课程/挑战作品提交、自然观察提交；
- 项目评论、作品评论、观察评论、自然观察鉴定、挑战评分；
- 消息发送；
- 课程项目保存、课时完成、项目探索、PBL 工作区/阶段保存和观察图片分析。

## 6. 错误契约

门禁错误为 HTTP 403，并包含稳定 `code`：

- `AGE_CONFIRMATION_REQUIRED`：登录有效，但需要完成本人年龄确认；响应中提供设置页跳转地址。
- `INTERACTION_RESTRICTED`：账号当前被限制互动。
- `AUTH_REQUIRED`：需要登录；匿名页面通常由前端打开登录层处理。

前端锁态负责提示、跳转和一次原请求重试，最终权限以 API 和数据库 RLS 为准。

客户端收到 `AGE_CONFIRMATION_REQUIRED` 后会暂存当前页面和原始写请求，跳转到本人年龄确认设置；确认成功后服务端重发原请求，并返回原页面继续显示成功或失败结果。用户直接打开设置页时不会触发任何重试。

## 7. XP 规则

浏览器不再可以提交任意 XP 金额。`POST /api/xp/increment` 已废弃并返回 `XP_EVENT_REQUIRED`。

业务服务通过 service-role-only 的 `award_xp_once(user, action, resource)` RPC 发放固定奖励。函数在同一事务中写入 `xp_logs`、更新 `profiles.xp`，并以用户、动作和业务资源做幂等约束。XP 奖励失败不能改变投稿或评论的成功结果，但必须记录服务端错误。

## 8. 后续边界

第一版先验证“公开浏览 → 注册 → 保存进度 → 需要互动时本人确认”的转化路径。后续若要锁定课程正文或高级挑战，应另行设计公开摘要、正文鉴权、附件私有化和缓存隔离，不能只给现有数据表加一个等级字段后继续 `select *`。
