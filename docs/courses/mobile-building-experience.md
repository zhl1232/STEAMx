# 手机积木搭建体验与小迪语音控制

更新：2026-10-12。本文区分用户观察、本次实现与后续方案；实现和测试通过不代表生产已发布。

## 使用场景与已确认约束

项目负责人观察到：孩子很大程度上按“想做什么作品”选课；成品可以玩时，会继续玩一会儿。带孩子搭建的人还要频繁操作手机，是当前明显的体验负担。这些是现有带课观察，尚不能当作外部目标家庭的规模化验证。

本轮确认：

- 手机课程目录需要显示作品成品图，让孩子和家长知道将要搭出什么。
- 连续切换 3D 搭建步骤时，保留家长已经调好的观察角度；不要强制旋转、套用新的关键视角或加入视角过渡动画。
- 尽量在同一屏看清模型、本步零件形状和数量，以及新增结构所在位置。提示保留积木原色，便于与手中材料对应。
- 搭完后的自由玩耍属于当前使用过程；本轮不增加强制分享、上传或立即进入下一课的步骤。

## 本次界面实现

### 成品选课

`course-lesson-catalog.tsx` 的既有成品卡模式在手机也显示两列图片卡；桌面延续 2/3/4 列。只渲染一套课时链接，避免同一课时产生隐藏的重复入口。该模式沿用课程详情页原有条件：课时达到目录阈值且全部属于 `building_3d`；普通课程列表和按阶段学习的课程不受影响。

图片继续使用已有 `finished_image_url → finishedImageUrl` 数据与懒加载，不增加逐课查询。图片完整包含在 4:3 区域内，缺失或加载失败时保留标题、状态和进入课时的链接。

### 搭建中的模型与材料

`building-3d-workspace.tsx` 在手机竖屏适当收紧画布与说明区域，本步零件使用两列小图、名称和数量。复用已有 `PartThumbnail` 与本地零件图；没有对应图片时使用颜色占位，图片不是目标颜色时沿用真实颜色标记。手机默认收起全课清单，优先显示本步材料；长清单在零件区内滚动。横向全屏沿用右侧单列材料区。

`lib/utils/ldraw-step-highlight.ts` 保留本步真实 LDraw 模型的原生边线，将已完成步骤的边线透明度降到原来的 25%，通过轮廓清晰度区分新旧结构。仅缓存并替换已有步骤的线材质，不修改线条颜色、积木面色、模型几何、零件清单或原有绘制批次；条件线保留原 shader 的视角显隐和深度测试，淡化线不写入深度。回看旧步会恢复该步的原线材质；进入空步、目标尚未加载或释放场景时恢复全部原线材质。迟到加载只服从当前选中步骤，模型之后的收尾页不会把最后一批零件继续标成新增。

初次浏览器检查发现统一橙色边线会把大板的密集凸点染成一整片橙色，影响按原色找零件，因此采用上述明暗方案，大板原有边线颜色规则也随之保留。

这项提示帮助识别新增结构，尚不等同于自动标出每个连接点；被遮挡的位置仍需家长按原有方式旋转查看。此次没有加入自动选视角、连接动画或透视显示。高亮改动针对真实 LDraw 分步模型，其他模型格式沿用原有展示逻辑。

### 连续翻步

普通 `focusStep()` 不触发相机重置；原有首次初始化和用户主动点击“视角”按钮的行为保留。首次模型加载等待期间也接收步骤变化，避免模型最后停在旧步骤。

`lesson-page-client.tsx` 复用 `buildBuildingLessonFlow` 判断当前页和目标页的种类：两页均为 `build` 时保留整页滚动位置；跨入或离开课件、视频时沿用原来的回到页首行为。零件区自己的滚动在切步时回到开头。课程 URL 中的页码、目录跳转与小迪工具仍使用同一个步骤导航入口。

## 小迪当前可以复用的能力

以下为 2026-10-12 的代码核查，不是已完成的真机麦克风验收。

1. 已登录、启用手机长按语音且允许麦克风时，可以长按收起状态的小迪录音，松手后转写并自动发送。面板内的麦克风则把转写填入输入框，仍需发送。录音、识别和回复状态已经有取消与场景隔离。
2. 现有聊天链路可产生 `course.focus_lesson_step` 工具；积木课页也注册了该处理器，最终调用与界面按钮相同的 `handleStepChange`。因此语音“进入下一步”具备现有接入基础，并非必须先重做整个导师。
3. 工具当前接收绝对 `stepIndex`，“下一页／上一页”由模型结合上下文推断；目前没有独立的确定性相对翻页指令入口。
4. 目前每次录音结束后上传一段音频。回复可以朗读，但播放结束不会自动再次监听；语音识别服务配置 `turn_detection: null`，收到音频后显式提交并结束会话。自动朗读不等于持续语音对话。

代码入口：`components/features/tutor/use-tutor-voice.ts`、`global-tutor-fab.tsx`、`use-tutor-chat-stream.ts`、`app/api/tutor/speech/transcribe/route.ts`、`lib/ai/tutor/speech.ts`、`lib/ai/tutor/tool-registry.ts` 与课时页客户端。

## 语音控制的后续方案与前置问题

本轮未实施持续监听。下一步优先讨论课程内明确开启的语音控制模式：开始搭建时开启，支持“下一页、上一页、暂停、退出”等有限动作，并给简短确认。连续翻页应使用课程展示页序，包含课件、视频和 3D 步骤，不能直接加减模型内部步号。

需要先处理的具体问题：

- **统一小迪与界面的步骤内容。** 界面使用 `buildBuildingLessonDisplaySteps`，服务端 `lib/ai/tutor/context-builders.ts` 的 `buildCourseContext` 当前仍读取旧 `course_lessons.steps`。同一个页码可能对应不同内容；修复后再验收“当前页是什么、下一页是什么”的讲解和操作。
- **避免迟到或重复翻页。** 明确指令的执行依据、当前课时与步骤版本；手动翻页、离开课程、暂停或退出后，旧识别结果不应突然改变页面。第一步、最后一步及反复触发也需要验证。
- **设计监听状态。** 需要明确开启、正在听、处理、确认播报、恢复监听、暂停和退出。第一版可在播报时暂停监听，再恢复收音，避免把小迪自己的声音识别为指令；完整可打断的持续对话另行评估。
- **复用边界。** 若在专门开启的控制模式下解析明确口令，可复用现有语音转写，再由确定性导航处理。这里的本地指令解析不代表离线语音识别；开放式提问仍走小迪原有语义链路。
- **验证连续操作的节奏。** 当前转写接口限制每分钟 10 次、每段至多 30 秒。语音控制需按实际翻页节奏核对识别延迟和限流，不应直接将现有长按流程无限循环。

是否进入这项实现，以用户后续确认的交互范围为准；不把“支持长按说话”当成已经解决双手被占用的问题。

## 验证范围

定向回归覆盖目录图片与失败回退、搜索与筛选、零件清单、步骤与 URL 导航、连续搭建页滚动、边线原色与几何保持、条件线、异步注册及资源释放。浏览器验收使用隔离的本地课程界面、真实仓库模型与本地资源，检查手机和桌面布局，以及旋转后前后切步的相机连续性。

2026-10-12 本地结果：7 个相关测试文件、75 项测试通过；本次模块及依赖的 TypeScript 检查和 `git diff --check` 通过。浏览器检查覆盖 390px / 320px 目录、390×844 与 320×568 搭建页、844×390 横向全屏和 1440×1000 桌面，未出现横向溢出；检查了原面材质、旋转后前后翻步、旧边线淡化及首步慢加载中的快速前后翻页。320×568 仍可能需要先滚到搭建区，连续翻步保持已找到的位置。浏览器夹具复用真实课程组件、全局样式和模型，路由、鉴权及 API 使用隔离替身；未写入生产数据。

发布前仍需在实际使用的手机上确认触控、浏览器工具栏变化和横屏全屏体验；小迪麦克风、真实识别及课程讲解不属于本轮 UI 验收。
