# 小迪代币计费与用量核算

更新：2026-10-12。本文说明本次代码和迁移提出的新规则；迁移尚未向生产执行，不能据此认定线上已生效。

## 产品规则

- 小迪按本次成功请求中可核验的模型总用量结算：输入与输出合计 **100 token = 1 代币**。
- 先汇总同一请求的所有实际模型调用，再兑换代币；不按调用次数向上取整。一枚 token 对应 0.01 代币，钱包沿用 `numeric(18,3)`，旧账单的 0.001 精度继续保留。
- 会员每月 1500 代币、每天 5 次免费机会沿用现有设置；PBL 草稿、点评与辅导继续采用原固定价格。这次修改小迪的消耗规则，不修改发放量或会员售价。
- 客户只看到代币余额、免费机会与本次扣除的代币。界面、当前对话、历史回看和请求重放都不显示原始用量或换算公式。
- 2026-09-20 的旧输出计费凭证仍按旧规则完成、退款和重放；已经结算的金额不追溯重算。

例如某轮输入 8000、主回复输出 500，相关后台调用另用 2100，合计 10600，费用为 106 代币。数字仅用于解释规则，不代表生产平均用量，也不等同于供应商的人民币成本。

## 计入范围与真实用量

`lib/ai/tutor/usage.ts` 创建每个已准入请求独享的 collector；通过显式 observer 传入共享 DashScope 客户端和各 helper，不使用全局或跨请求的隐式计量状态。

| 调用用途 | 收集位置 |
|---|---|
| 主回复，含实际文本或视觉调用 | `engine.ts` 与 `dashscope.ts` |
| 资源规划及必要的重试 | `resource-search-planner.ts` |
| 页面工具规划 | `tool-call-planner.ts` |
| Scratch 截图诊断 | `scratch-screenshot-diagnosis.ts` |
| 鸟鸣挂件选择，包括后来未采用的早期调用 | `audio-tags.ts` |
| 用户长期记忆与会话滚动摘要 | `memory.ts` 与摘要模型出口 |

数据库查询、规则匹配、资源列表整理本身不产生模型 token，不另外虚构用量。全站运营任务和其他用户的调用不进入本请求。

每个真实上游 attempt 都有独立记录，结束回调幂等。成功请求中，重试或降级前已经产生且可核验的用量也计入；整体请求失败、无有效回复或确认保存失败时沿用取消与释放预留规则。供应商仍可能产生未向用户收费的失败成本。

归一化遵循以下边界：

- 接受合法的供应商 `totalTokens`，或者完整的 `promptTokens + completionTokens`。
- 同时返回两种口径时必须一致；非法、负数、小数或不安全整数不参与收费。
- 推理量是输出的一部分，不再从输出扣除，也不重复相加；过滤推理正文不会免除已核验的模型用量。
- 仅有总量但缺少可拆分的输入/输出时，保留总量，细分字段为 null，不假造拆分值。
- 缺失用量的调用不估算收费；其他已核验调用照常结算，并在私有记录中标记缺失。预估量只用于执行预算。
- 成功结算前所有本轮模型调用必须结束，不能把仍在运行的调用遗漏到下一轮账单。

## 摘要与结算时序

原流程在回复完成与扣费之后通过 `after()` 运行摘要，无法纳入已完成的账单。

新流程在主回复生成后、消息与扣费的最终事务之前，等待需要执行的两类摘要。摘要仅处理此前已保存的消息，本轮即将保存的问答在后续请求中达到门槛后纳入。原有阈值和游标比较后更新机制保留；摘要失败不阻断有效主回复。成功澄清也结算为它实际执行的规划与记忆工作。

早期鸟鸣规划即使被后来的选择替代，也会先等其结束，再汇总两个调用。结算之后不再为这轮启动新的文本模型任务。

跨场景同时触发同一用户的记忆维护仍使用现有乐观并发控制；本次没有新建跨场景摘要生成锁，不能声称已消除所有重复摘要成本。

## 余额预留与执行预算

服务端先预留整轮额度，再开始收费模型调用。新上限为 `TUTOR_MAX_TOTAL_TOKENS = 131072`，主回复输出上限独立保留 `8192`；钱包按实际可用余额缩小整轮预算，最小结算单位为 0.01 代币。免费请求继续受每天次数和单请求预算约束。

collector 在每次调用前同步预留其输入估计量与输出上限，涵盖并发在途调用。文本按字节和结构开销给保守预算，图片有独立执行预留；这些值不是精确分词或收费凭证。主回复可缩小输出上限；可选规划或摘要预算不足时停止相应调用。新增显式输出上限：截图诊断 256，用户摘要至多 1800，会话摘要 800。

若少量钱包余额无法容纳主回复的实际执行预留，主调用会在发送供应商请求之前，尝试一次 `fallback_tutor_usage_to_free_service`。数据库核对原用户、请求、执行器、凭证、预算不足和剩余免费次数，原子退还钱包预留，并为同一请求关联一条免费配额子流水；主凭证与已有模型调用保留，不重跑。收到确认后才扩大原 collector 的预算，已知、缺失和在途调用的占用不会清空。免费额度耗尽或切换结果未确认时不扩容；本来已经使用完整预算的请求也不能再申请一次免费额度。子流水使用 `quota_*` 状态，后台只统计一次主凭证。取消或过期退回其免费次数，不再次退还钱包。

供应商实际用量超过预估时阻止预算不足的后续调用；数据库费用始终以原预留为上限，保留实际用量与超出预留的差额，不透支钱包。该机制限制本次执行范围，不保证估算与所有模型的真实分词完全一致。

## 账单、原始记录与权限

新流程使用：

- `reserve_tutor_usage_service`：绑定用户、请求和整轮预算。
- `begin_tutor_usage_request_service`：持久化请求身份、执行器与额度。
- `fallback_tutor_usage_to_free_service`：主调用预算不足时，将同一请求原子切换到剩余免费机会。
- `settle_tutor_usage_service`：汇总用量、释放余量并生成代币账单。
- `complete_tutor_usage_request_service`：两条消息、扣费、终态在同一事务中提交。

原始调用明细与预算放在 service-role-only 的 `tutor_usage_records` 中；可空的 `free_quota_receipt_id` 关联预算回退时使用的免费配额流水。新的客户消息与钱包流水不存原始用量明细；公共 `TutorBilling` 只包含 `source`、`chargedCredits`、`receiptId`。解析历史账单时只提取这三个字段，保留旧金额。

现有请求与凭证幂等、用户锁、20 分钟过期、删除历史及跨月退款保护继续有效。应用重试使用同一个请求与执行器身份；不确定是否提交成功时，不退款后重新生成。管理员用量统计同时识别新旧凭证，只累计已结算金额，忽略预留、取消和过期记录。

## 语音费用边界

本次没有实现持续语音对话，也没有新设语音的代币兑换规则。

当前语音转文字默认 `qwen3-asr-flash-realtime`，合成默认 `qwen3-tts-flash-realtime`，普通合成有 fallback；实际部署可由环境变量覆盖。ASR 按音频时长、TTS 按输入字符计价，当前语音接口未将这些用量接入代币结算，不能当作文本 token 加到此次总量。

持续语音上线前需要独立决定时长/字符的计量及代币规则，并验证识别频率、连续监听、播报串音与实际成本。是否上传整段录音、每轮历史长度、回答长度及模型选择都会影响费用；当前代码候选模型列表不能替代线上实际模型与账单数据。

官方参考（2026-10-12 核对）：

- [Qwen3 ASR Flash Realtime](https://help.aliyun.com/zh/model-studio/qwen3-asr-flash-realtime)：北京原价每输入音频秒 0.00033 元。
- [Qwen3 TTS Flash Realtime](https://help.aliyun.com/zh/model-studio/qwen3-tts-flash-realtime)：北京原价每万输入字符 1 元。

以上是供应商原价，未计免费额度或活动，也不是本平台代币售价。
