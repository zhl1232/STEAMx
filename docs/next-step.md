## 信任等级与内容访问控制

### 方向判断

- **优先级**：P0-P1（先修复现有奖励与等级口径风险，再开放内容门禁）。
- **产品定位**：新增独立的 T0-T4 信任等级，用持续参与、有效贡献和社区行为控制内容阅读与社区操作；XP 等级、信任等级、会员和角色保持四条独立轴。
- **产品方案**：见 [`TRUST_LEVEL_AND_CONTENT_ACCESS.md`](./TRUST_LEVEL_AND_CONTENT_ACCESS.md)。
- **开发设计**：见 [`TRUST_LEVEL_AND_CONTENT_ACCESS_IMPLEMENTATION.md`](./TRUST_LEVEL_AND_CONTENT_ACCESS_IMPLEMENTATION.md)。

### 能力范围

- **P0 前置治理**：收紧当前允许登录用户提交任意 `1..1000` XP 的 `POST /api/xp/increment`；统一动态 XP 等级与 `profiles.level` 的读取口径，避免评论图片、商店和页面展示使用不同等级。
- **内容门禁**：课程、项目、挑战和资料逐条显式配置最低信任等级；目录、封面和简介公开，完整正文与资源由服务端统一判定是否可读。
- **社区权限**：T1 开放投稿和评论回复，T2 开放发帖和私信；T3/T4 可阅读对应等级内容，T4 由管理员从 T3 人工授予并记录原因。
- **会员旁路**：有效会员只可旁路已发布内容的阅读门槛，不能旁路投稿、评论回复、发帖或私信门槛。
- **晋级与迁移**：T1-T3 按账号时长、活跃日、审核通过贡献、互动和违规记录自动晋升；老用户按历史数据回算且自动最高到 T2；v1 不因单纯不活跃降级。
- **强制执行**：前端锁态只负责解释，API、服务端数据加载和必要的 RLS 才是权限边界；统一访问判定需返回稳定 reason code 供 UI 展示。

### 非目标

- 不复用 XP Lv. 作为信任等级，不按内容难度自动推导访问门槛。
- 不让会员或普通角色自动获得社区操作权限。
- v1 不做仅因长期未登录而自动降级；确认违规走冻结、降级或人工覆盖。

### 建议迭代顺序

1. **P0：封堵奖励与等级风险**：下线任意 XP 自增入口，统一 XP 等级来源并补越权/重复奖励测试。
2. **P1：信任数据与判定器**：落地 T0-T4 状态、晋级证据、违规冻结/人工覆盖和统一服务端授权函数。
3. **P1：内容配置与双层响应**：为四类内容补最低等级配置，将公开摘要与受保护正文/资源拆开，并在 API/RLS 强制执行。
4. **P1：社区操作门禁**：依次接入投稿、评论回复、发帖和私信，补会员旁路边界。
5. **P1：历史回算与灰度**：先只记录判定结果，再灰度启用门禁；老用户自动最高 T2，监控误拦截后再扩大范围。
6. **P2：T3/T4 运营**：开放 T3 自动晋升与 T4 管理员授予、审计和撤销流程。

- **保留动态能力**：如果后续记录量变大，再补充「鉴定 / 评论 / 全部动态」筛选或时间线视图。

## 自然观察：地域化与动态预警

2. **P1：首季 MVP**：赛季页入口、任务列表、等级奖励领取；接入现有 coins/徽章发放流水。
