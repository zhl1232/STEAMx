## AI Tutor Agent 化深度集成

### 方向判断

- **优先级**：P1（Agent 运行时骨架、PBL 首个 handler、课时步骤聚焦 handler、Scratch iframe 内积木关键词提示/分类切换与 flyout 具体积木定位已落地，下一步应继续到 Playground 棋盘级提示或扩大 Scratch opcode 覆盖）。
- **产品定位**：将小迪从「对话式导师」升级为可调用工具的 Agent，能直接与产品 UI 交互，而不只是输出文字建议。
- **技术基础**：已有 tutor 引擎、场景上下文、图片来源校验、代币门禁与对话线程；可复用 Qwen Vision 做棋盘、Scratch 或作品截图识别。

### 能力范围

- **工具调用通道扩展**：现有 tutor 流式回复之外已有结构化 `tool_call` 通道，后续可接入更多白名单工具。
- **场景级 handler 扩展**：前端已支持当前场景注册受控 tool handler；Scratch 课时已支持当前步骤聚焦、iframe 内积木关键词提示、分类切换与 flyout 具体积木定位，后续扩展到 Playground 棋盘级提示等场景。
- **典型能力示例**：
  - Scratch 卡关：已可按当前步骤在主站与 Scratch iframe 内提示相关积木关键词，尝试打开对应分类，并在 flyout 中定位匹配积木；后续可继续扩展更多 opcode 映射或结合截图判断用户当前缺哪块。
  - 扫雷 / 迷宫：基于当前棋盘状态给出可视化下一步提示。
  - PBL 阶段：已支持在「我卡住了 / 下一步 / 看看反馈」意图中展开并高亮当前阶段；后续可细化到缺失检查项或相关材料入口。

### 非目标

- 暂不做跨页面无约束 UI 自动化。
- 暂不代用户点击提交、代发帖或代报名。
- 暂不做多 Agent 编排或长期自主任务链。

### 建议迭代顺序

1. **P1：Playground 棋盘提示或 Scratch 定位增强**：例如做迷宫 BFS / 扫雷安全格提示，或扩大 Scratch 具体积木定位的 opcode 覆盖与截图诊断，复用现有「对话 -> tool_call -> 场景 handler -> UI 反馈」链路。
2. **P1：工具调用策略升级**：从确定性意图规则扩展到模型受控工具选择，但仍保持服务端白名单、payload 校验与前端受控 handler。
3. **P2：技能池运营**：按 `xxx-skill` 规范沉淀更多场景 skill，Admin 可配置启用范围与代币消耗策略。

## 自然观察：地域化与动态预警

### 方向判断

- **优先级**：P2（自然观察核心流与物种库稳定后推进）。
- **产品定位**：结合地理围栏与时令数据，做地域化运营与动态季节活动，增强户外探索的沉浸感与回访动机。
- **与现有能力关系**：复用自然专题、物种 slug、观察提交、XP/徽章；与个人主页「自然待观察物种」和小迪 species 场景联动。

### 能力范围

- **地域物种库**：针对特定地域维护本地物种子集或运营位，与全国物种库并存。
- **时令与活跃期**：配置迁徙季、羽化期、开花期等信号；进入活跃窗口时触发运营事件。
- **季节限时打卡挑战**：动态生成「本季必观察」清单或限时挑战，完成后发放专属徽章/时间线条目。
- **地理围栏（可选）**：用户授权定位后，在公园/保护区范围内增强物种提示或「此地常见」卡片。

### 非目标

- 暂不做实时物种追踪或第三方生态 API 强依赖。
- 暂不做全站强制 LBS；地域化内容为增强层。

### 建议迭代顺序

1. **P2：地域与季节配置模型**：后台可配置「地区 x 物种 x 时间窗口」运营单元。
2. **P2：动态挑战生成**：按当前日期与地区渲染限时打卡任务，接入现有提交与徽章体系。
3. **P3：定位与围栏**：可选 GPS 围栏、本地化推送与地图层「当季热点」展示。

## 动态经济系统与赛季运营

### 方向判断

- **优先级**：P1-P2（XP/金币/徽章/商店闭环已具备，适合在核心学习路径成型后叠加运营层）。
- **产品定位**：引入探索季、观鸟季、通行证等限时运营单元，让奖励与任务随赛季变化。
- **与现有能力关系**：复用 XP、coins、badges、shop、挑战投稿、自然观察、PBL 进度；Admin 后台可扩展赛季配置。

### 能力范围

- **赛季配置**：后台定义赛季名称、起止时间、主题视觉、免费轨/预留付费轨奖励表。
- **赛季任务与进度**：完成指定 PBL 挑战、提交自然观察、游乐场对战胜场等任务，升级解锁奖励。
- **动态倍率与限时商品**：赛季期间特定行为金币倍数；商店轮换限时头像框、名字颜色等商品。
- **绝版与收藏**：赛季专属徽章/头像框进入徽章墙与资料页展示。
- **跨模块联动**：与自然观察地域化、PBL 工作台共用赛季 ID，避免多套运营配置冲突。

### 非目标

- 暂不做二级市场或玩家间交易。
- 暂不强制 IAP；首版以免费通行证和任务驱动为主。
- 暂不做跨赛季积分继承。

### 建议迭代顺序

1. **P1：赛季数据模型**：`seasons`、`season_tiers`、`season_tasks`、用户赛季进度表；Admin CRUD 与上下线时间。
2. **P1：首季 MVP**：赛季页入口、任务列表、等级奖励领取；接入现有 coins/徽章发放流水。
3. **P2：动态商店轮换**：商店按赛季过滤/高亮限时商品；倍率规则引擎。
4. **P2：全站赛季触点**：首页 Banner、个人主页进度卡、挑战/自然频道赛季标签。
5. **P3：通行证进阶**：更长周期、更多任务类型、与游乐场多人战绩挂钩。

## 自然观察：新专题扩展

### 方向判断

- **优先级**：P2-P3。
- **核心认知**：观察系统本质是「有限类型清单 + AI 鉴定 + 社群共识 + 已观察/待观察进度」引擎。只要某类对象能列成有限、可枚举的类型清单，就可以复用。

### 未完成范围

- **矿物岩石专题**：新增 `nature_topic`，配置岩矿类型清单；隐藏生命阶段/性别，保护提示改为「不破坏地貌、不私自采集」。
- **云类型专题**：只做「云的类型」，按云属建立有限清单；不做晴/雨/雪等天气状态专题。
- **真菌专题**：当前仍作为预告；需补齐真菌物种数据后再开放提交、鉴定与进度。

### 非目标

- 不做无法枚举成清单的天气状态专题。
- 不做海鲜河鲜这类与自然观察距离较远、需要新建水产清单的大专题。

### 建议迭代顺序

1. **P2：矿物岩石专题**：新增专题、类型清单、非生物字段隐藏和提示文案。
2. **P3：云类型专题**：按云属建类型清单，复用鉴定、共识与进度。
3. **P3：真菌专题**：有稳定数据后启用提交和鉴定流程。
